## 1. 准备

| 工具 | 版本 | 什么时候需要 |
|---|---|---|
| Node.js | ≥ 22.12 | 一直需要 |
| Python | 3.12（CI 用的版本） | 只在用 Python 训练时需要 |
| Foundry（`forge`、`anvil`） | ≥ 1.8.0 | 只在部署到链上或运行合约测试时需要 |
| 浏览器 | 新版 Chrome、Edge 或 Safari | 一直需要 |

在仓库根目录安装依赖：

```sh
npm ci
```

## 2. 启动工作台

有三种启动方式。先用第一种。

| 方式 | 命令 | 地址 | 适合 |
|---|---|---|---|
| 开发服务器 | `npm run dev` | 终端显示的地址，默认 `http://localhost:5173/` | 试用、改源码 |
| 单文件 | `npm run build`，然后打开 `frontend/dist/neurom-studio.html` | `file://…` | 离线演示、只用浏览器训练 |

不要用 `python -m http.server` 服务 `frontend/` 源码。源码里有 TypeScript 和 Vue SFC，浏览器不能直接运行它们。

- 右下角：「选中」「全览」和缩放比例。
- 底部：状态栏。连线被拒绝时，这里写出原因。

## 3. 五分钟体验：组合器

组合器带有内置产物，所以不用训练就能看到结果。

1. 打开 `http://localhost:5173/?preset=arithmetic-combiner`。也可以在「添加」抽屉的「示例」里点「组合器 · 内置 ADD4 / SUB4 / MUL4 与策略产物已接受」。
2. 按 `F`，让画布显示整个训练模块。
3. 在左栏找到评估器「按运算评估」，点「评估」。
4. 在执行实例里，把回合下标改成 `88`。
5. 点「重置」，再点「走一步」。
6. 选中右边的回路框，再点右下角的「选中」，放大回路框。

你应该看到这些结果：

- 评估报告：测试分区 154 个回合，`exact` 均值 1。按 `op` 分组后，`*`、`−`、`+` 三组都是 1。
- 执行实例：下标 88 的测试回合是 `{index: 440, a: 9, b: 2, op: −}`。这一步「调用 SUB4（内置）」，答案的 `action` 是 7，结果「成功」。
- 回路框：SUB4 高亮，ADD4 和 MUL4 变暗。`State` 显示 `t 1 / 1`，`action` 显示 7。

模块标题来自模板。所以切换到英文界面后，有些标题仍是中文。

## 4. 训练第一个模型：挖矿

挖矿任务没有内置产物。你要自己训练一个网络。

1. 如果工作区里有要保留的内容，先点「保存工作区」。
2. 在「文件」抽屉里点「清空整个工作区」。
3. 打开 `http://localhost:5173/?preset=mining-task`。
4. 在训练器上确认 `backend` 是 `browser`。
5. 点「开始训练」。训练器显示进度条、loss 曲线和验证指标曲线。
6. 训练结束后，在候选上点一个候选的「接受」。
7. 在执行实例上点「重置」，再点「运行」。
8. 看地图视图。视图画出玩家的轨迹、视野和基地。

<p align="center"><img src="images/mining-overview-zh.png" alt="挖矿训练模块：左栏是数据、环境、目标、训练器和结果，右边是回路框" width="100%"></p>

- 训练用时约 35 秒。
- 验证指标 `validationMetric` 是 17.859。
- 测试回合 0 跑满 63 步，结果「成功」。

训练只产生候选。你接受一个候选后，权重才流向网络。训练开始后再改画布，不影响正在运行的训练。

要从已接受的权重继续训练，把候选的 `weights` 接到训练器的 `init`。下一次训练从这个产物开始，不从随机权重开始。训练器先验证起点，记为第 0 轮。只有更好的一轮才能替换起点。产物的网络结构和读出必须和被训练的网络相同，否则训练器报告问题（ADR 0020）。

要让训练等上一阶段过关，把评估器的 `report` 接到训练器的 `gate`。然后在训练器里选择这个评估器的一个指标，再填写最小值（≥）或最大值（≤）。点“开始训练”时，训练器读取这个评估器当前的报告。下面几种情况不开始训练，训练按钮下面写出原因：

- 还没有报告。
- 报告已经过时：评估以后，评估器的训练快照又改变了。
- 报告里没有这个指标。
- 指标没有达到条件。

训练器只在开始时检查条件。训练进行中报告变化，不中断训练。浏览器后端和 Python 后端都一样：工作台在开始训练前检查条件，然后才把训练交给后端。报告是会话状态，不随工作区保存。所以重新打开页面以后，先在评估器上点“评估”，再开始带 `gate` 的训练（ADR 0020）。

注意：训练时不要关闭页面。浏览器训练在 Web Worker 里运行，关闭页面会中断训练。重新打开后，这次运行标为失败。

## 5. 改规则

规则写在训练模块左栏的模块里。改这些模块，不用改代码。

- 环境参数：网格边长、步数上限、背包容量、资源概率、价值和结算方式。
- 感知参数：方形视野半径。
- 奖励权重：每步成本、无效动作成本、成功奖励、失败成本、价值系数。
- 代码：场景（`init`、`input`、`step`、`budget`、`actions`）、奖励和指标。

参数的范围写在声明里。值越界时，模块报错，并且画布阻止打包。

代码模块有角色页。被别的模块按协议调用的函数，各有一个竖向 tab。

- 函数头按协议锁定。参数可以改名，但是不能增删。
- 点行尾的 **?**，打开说明窗。说明窗写出谁在什么时候调用它、参数、返回值和一个真实运行的例子。
- 把鼠标停在一个名字上，查看它的类型和说明。
- 类型错误画波浪线，并列在编辑器下方。

<p align="center"><img src="images/mining-code-zh.png" alt="奖励函数的角色页和说明窗" width="80%"></p>

改了场景、`budget` 或驱动分区的回合种类后，候选把旧产物标为“环境不同”。这时你要重新训练。

## 6. 用 Python 训练

Python 后端用 PyTorch 训练同一份训练快照。

1. 构建单文件页面：

   ```sh
   npm run build
   ```

2. 安装 Python 依赖：

   ```sh
   python3 -m venv ~/.cache/neurom-venv
   ~/.cache/neurom-venv/bin/python -m pip install -r training/requirements.txt -r training/requirements-torch.txt
   ```

3. 启动 Workspace：

   ```sh
   ~/.cache/neurom-venv/bin/python training/workspace.py --port 18766
   ```

4. 打开 `http://127.0.0.1:18766/`。顶栏显示「Python 工作区已连接」。
5. 在训练器上把 `backend` 改成 `python`，然后点「开始训练」。

开发服务器把 `/api` 代理到 `127.0.0.1:18766`。所以 Workspace 运行时，`npm run dev` 打开的页面也能用 Python 训练。Workspace 持有 Python 运行。刷新页面后，页面重新接上这些运行。

离线训练、快照格式和给 AI 的任务书见 [AI / Python 训练指南](ai-module-training.md)。

## 7. 部署到本地链

本节在本地 Anvil 上部署 ADD4，然后发一笔 step 交易。

1. 在第一个终端启动 Anvil：

   ```sh
   anvil --network monad --port 18545
   ```

2. 在第二个终端部署协议合约。如果节点是新启动的，必须先做这一步。

   ```sh
   cd contracts
   forge script script/Deploy.s.sol --rpc-url http://127.0.0.1:18545 --unlocked --sender 0xf39fd6e51aad88f6f4ce6ab8827279cfffb92266 --broadcast
   ```

   输出里的 `factory` 应该是 `0x9fE46736679d2D9a65F0992F2272dE9f3c7fa6e0`。这是 `frontend/chain.js` 里 31337 的官方 Factory。

3. 在空画布上打开 `?preset=arithmetic-add4`。
4. 在「添加」抽屉的「空白模块」里点「+ 链上部署」。
5. 从训练模块右侧的 `cands · artifact` 端口拖一根线，接到链上部署模块的 `artifact` 输入。

7. 点「部署当前产物」。然后点「核对链上模块」。

## 8. 保存、分享和模板

- 工作区自动保存在浏览器的 `localStorage`（键 `neurom-workbench`）。产物很大，所以它们按内容 id 存在浏览器的 IndexedDB（`neurom-artifacts`）里，`localStorage` 只记下它们的 id。IndexedDB 里的产物不自动删除。不同的端口和域名各有一份保存。
- 「保存工作区」把整个工作区导出成 JSON 文件。「打开」导入这个文件。要在别的地址使用工作区，先导出，再导入。
- 如果文件打不开，状态栏写出格式、出错位置和原因。当前工作区保持不变。
- 选中模块或组合，再点「存为模板」，就得到一份模板。「模板」抽屉里可以实例化、分叉、导入和导出 YAML 模板。
- 实例不随模板更新。每个组合的标题旁显示来源 `模板 id@revision`。

## 10. 脚本模块

脚本模块运行你写的 JavaScript，并把结果画成视图。它只做推理。训练快照不包含它，它也不改变环境哈希（ADR 0019）。

1. 点「添加」。
2. 点「脚本模块」。
3. 点「单步」。
4. 点「运行」。
5. 点「暂停」。
6. 点「重置」。
7. 点「✎ 编辑代码」。
8. 在文件列表下面输入文件名。
9. 点「＋ 文件」。
10. 点「保存并重新运行」。

每一步的结果：

- 新模块带一个计数器示例。
- 「单步」让计数和「第 n 轮」各加 1。
- 「运行」让计数连续增加，「暂停」让计数停下。
- 「重置」重新启动 `main`，计数回到 0。
- 编辑器左边是文件列表，右边是代码。
- 「保存并重新运行」用新代码重新启动脚本。「取消」丢掉没有保存的修改。

`main.js` 不能删除。

`main.js` 的默认导出是 `{ layout, views, main }`：

- `layout`：CSS grid 的 `columns`、`rows` 和 `areas`。如果没有 `layout`，视图按自动换行的 grid 排列。
- `views`：把 `areas` 里的格子名映射到 Vue 组件。每个组件收到 `state` 和 `run` 两个 prop。
- `main(ctx)`：你自己写的循环。每一轮开头写 `await ctx.frame()`。`ctx.state` 是视图读取的响应式数据。

```js
import { Controls } from '@ui';
import { Board } from './views.js';

export default {
  layout: { columns: '1fr 160px', rows: '1fr', areas: ['board side'] },
  views: { board: Board, side: Controls },
  async main(ctx) {
    ctx.state.t = 0;
    while (true) {
      await ctx.frame();
      ctx.state.t += 1;
    }
  },
};
```

`run` 有这些成员：

- `reset()`、`step()`、`play()`、`pause()` 和 `toggle()`：重置、单步、运行、暂停，以及在运行和暂停之间切换。
- `steps`：当前轮数。
- `running`：是否在连续运行。
- `done`：`main` 是否已经结束。

`import { Controls } from '@ui'` 得到内置的运行按钮。文件之间用 `import` 引用，例如 `import { Board } from './views.js'`。导入的名字取导入时的值。

拖动模块的右下角可以改变大小，视图跟着自适应。脚本出错时，模块在「✎ 编辑代码」下面显示文件、行号和错误信息。脚本在视图脚本的沙箱里运行，不能访问工作台、存储和网络。

### 输入：调用网络和代码函数

脚本模块可以调用接进来的网络和代码函数，也可以读取接进来的值。

1. 点「✎ 编辑代码」。
2. 在「函数输入」下面输入名字，例如 `红方`，然后点「＋ 函数输入」。
3. 在「值输入」下面输入名字，例如 `p`，然后点「＋ 值输入」。
4. 点「保存并重新运行」。
5. 把一个读出的 `ƒ run` 或代码模块导出的函数接到模块左边的函数输入。
6. 把一个值（例如参数模块的 `params`）接到值输入。

每一步的结果：

- 每个名字在模块左边成为一个端口。函数输入的端口带 ƒ。
- 编辑器在每个名字下面写出接进来的模块。没有保存的名字写“保存后生效”。
- 改名时，连线跟着名字走：一个列表的个数不变时按位置，否则按名字。

在脚本里：

- `await ctx.call.<名字>(…参数)` 调用一个函数输入，得到结果。
- `ctx.values.<名字>` 读取一个值输入。

```js
const bits = await ctx.call.view(state, 0);
const out = await ctx.call.红方(bits);
const grid = ctx.values.p.grid;
```

页面在沙箱外执行每次调用，只把结果送回脚本：

- 网络通过它的读出的 `run` 执行：参数是一个 0/1 位数组，结果是读出的位。bits 读出和 argmax 读出都可以。网络用它已接受的权重，并且每次调用都从零状态开始，不保留记忆。
- 代码函数按它的程序执行，读它所在文件的输入和常量。参数可以是数、布尔值、字符串、数组和记录。
- 「重置」以后，旧一轮还没有回复的调用被丢弃。

这些情况会报告问题：

- 声明了函数输入，但是没有接线。
- 同一个名字声明了两次，或者既是函数输入又是值输入。
- 接进来的网络正在被训练器训练。和工具层的规则一样，这样的网络不能被调用。冻结一个副本：另加一个网络模块，结构相同，`weights` 接到候选。

调用没有声明的名字、读取没有值的值输入、或者调用失败时，脚本在那一行得到一个错误。没有捕获的错误显示在「✎ 编辑代码」下面。

场景导出的函数如果接到了脚本模块，场景检查不会把它当作拼错的角色。

## 内置任务

### 挖矿

挖矿（`mining-task`，REINFORCE）：玩家在网格上挖土 / 煤 / 金。玩家可以原地收工，也可以回基地交付。环境参数包括：

- 2–16 格的边长。
- 步数。
- 背包容量。
- 资源分布和价值。
- 结算方式。
- 基地。
- 目标价值。
- 交付后是否结束回合。

感知参数只有方形视野半径（1..4）。奖励系数是单独的参数模块。

默认规则（ADR 0018）：

- 16×16 网格，63 步，背包容量 3。
- 空地 / 土 / 煤 / 金的概率是 0.67 / 0.2 / 0.1 / 0.03。
- 价值：土 1，煤 2，金 10。
- 在基地结算，目标价值 1。
- “交付后结束回合”默认关闭。交付清空背包，回合继续到步数上限，所以玩家可以多次往返。

场景模块的 `input` 编码成 185 个输入位：

- 9×9 方形视野里每格的煤和金，各一位（81 + 81 位）。土和空地读 0。半径外或地图外的格读作空地。
- 基地的相对 x / y 偏移（各 5 位，+15）。
- 背包里的土 / 煤 / 金（各 2 位，到 3 饱和）。
- 背包已满（1 位）。
- 剩余步数（6 位）。

`input` 不给出最近目标的方向或距离。删掉一项，网络就收不到这一项。你也可以把这一项换成同宽的 0，保持布局。环境参数和感知参数都不会进入网络。

网络有 7 个动作槽。读出映射表里设为“无效”的槽是无效动作，它消耗一步。地图的随机数来自随机数模块的 32 位线性同余表，在 IR 里逐位确定。默认网络是 FF 185→32→7（`dense-policy`，int8 权重）。奖励是结算价值的增量。成功 = 至少交付一次，目标价值 1。

### 记忆地图

记忆地图（`memory-map-task`，交叉熵）：6×6 网格，起点 (2,2)。目标从其余 35 格中选择。一个回合分三段：

- 预览：目标显示一次，然后隐藏。
- 等待：等待 D 次。
- 寻找：最多用 8 步寻找目标。

预览和等待阶段的动作不移动玩家。目标隐藏后，`input` 不编码目标。最短路教师 `target(state)` 直接读状态里的目标，产生训练标签。网络看不到目标。默认网络是 LIF 55→32→7，用 int16 权重（`weightBits: 16`）。记忆地图没有内置产物。

评估器按延迟分组，给出保留曲线。测试分区有 35 个目标 × 延迟 0/1/2/4/8/16 = 210 回合。

每次训练、每个种子的结果都不同。这是有限域上的记忆诊断，不是新地图上的泛化。

### 四位算术

四位算术（`arithmetic-add4 / sub4 / mul4`，hinge）：三个阈值网络，结构是 8→12→5、8→16→5 和 8→112→8。每题一步。全部 256 组都枚举。内置产物是 int8，准确率 100%。

### 组合器

组合器（`arithmetic-combiner`，REINFORCE）：题目是 `op ∈ {*, +, −}` × a × b，共 768 题。题目按下标 mod 5 分成训练 / 验证 / 测试。策略网络只有一个工具层 `{ tools: tools, data: 8 }`。工具层的决策头直接读 11 个输入位 `op ‖ a ‖ b`。决策头选出冻结的内置 ADD4 / SUB4 / MUL4 之一，并决定交给它的 8 个数据位。

只有选中的网络运行。选中网络的结果位（零扩展到 8 位）就是答案。内置策略产物（int8）在 154 道测试题上全对。每题都选了对应的网络，交给它的正是 a‖b。

### 坦克大战

坦克大战（`tank-battle`，分阶段训练）：用 Botzone Tank2 规则的坦克对战，每方 1 辆坦克，2 条命。地图的两端各有一个基地。模板有 4 个训练模块，每个训练模块训练一个网络。阶段 1 · 模仿和阶段 2 · 对战训练各有“中”和“大”两个。两个阶段打同一种对战：网络开第 0 方的坦克，场景里的机器人开第 1 方的坦克。阶段 1 用交叉熵模仿场景里的教师。阶段 2 从阶段 1 的权重开始（ADR 0020），用强化学习和机器人对战。训练以后，脚本模块“坦克对战”让“中”和困难机器人对战，也可以让两个阶段 2 的网络对战（ADR 0019）。

规则写在场景模块里。它们照 [Botzone Tank2](https://wiki.botzone.org.cn/index.php?title=Tank2)，只有 4 处不同：每方 1 辆坦克而不是 2 辆，每辆坦克有 2 条命，不合法的动作当作等待而不是判负，对射以后的一步两方随机移动或者等待。选这套规则和地图的理由见 ADR 0024。

- 地图是 9×9。格子有空地、砖墙、钢墙、水和基地。固定的部分：第 0 方的基地在底部正中 (4, 8)，第 1 方的在顶部正中 (4, 0)。基地的左右和前面是砖墙，中间一列也是砖墙，这和 Tank2 的固定部分相同。中间一行只有 (3, 4) 和 (5, 4) 两格砖墙，其余是钢墙和水。所以两方都要从这两个通道过去，常常在中间相遇。顶部两行和底部两行也是固定的。
- 河两岸（第 2、3、5、6 行，中间一列和地图边上的水除外）每局随机。种子决定左上角四分之一的 7 格，每一格左右镜像，再转 180°，所以一格决定全图的 4 格。地图因此左右对称，转 180° 以后也不变。这 7 格里最多 2 格是钢墙或水（钢墙和水各一半），其余每格有一半的概率是砖墙。通道前面的 (3, 3) 不放钢墙和水，(1, 2) 和 (2, 3) 不同时放。所以坦克总能走到每一格空地和砖墙。种子 1 到 200 给出 190 种不同的地图。
- 每方的坦克从自己一边底部两行的 10 格空地里的一格出发。两方的出发格由种子各自选。
- 有 9 个动作：向上、右、下、左移动一格，向上、右、下、左开火，等待。坦克的朝向只用来画图，开火的方向在动作里。
- 不合法的动作当作等待：移动的目标格在下指令时不是空地或者有坦克，或者上一步开过火还要开火（开火的冷却是 1 步）。
- 一步里先结算移动，再结算开火。两辆坦克可以同时走进同一个空格，然后重叠。重叠的坦克打不到对方。
- 炮弹是射线，这一步就打到第一格不是空地也不是水的格：砖墙和基地被打掉，打到坦克就击中它，钢墙和地图边不变。炮弹飞过水。炮弹不分敌我，所以也能打掉自己的基地。
- 对射：两方都开火，并且各自打到对方的坦克时，两发互相抵消。两方的开火都不算，所以两方都不用冷却。
- 对射以后的一步：两方都不用自己的动作，而是各自从 4 个移动和等待里随机选一个，不能开火。随机数用回合种子、步数和这一方，所以同一局可以重复。每方只有 1 辆坦克时，面对面的两辆坦克会一直对射到步数用完。这一步打破这种僵局。
- 坦克被击中时少 1 条命。还有命时，它在这一步的最后回到自己的出发格，下一步照常行动。
- 基地被毁或者没有命的一方输。两方在同一步都输，或者走满回合步数（100），是平局。
- 每一步，场景在状态的 `trails` 里记下每一方的炮弹：出发格、方向、打到第几格和打到了什么。打到的可以是砖墙、钢墙或地图边、基地、坦克，或者对射抵消。`hits` 记下这一步被击中的坦克。

训练用的规则（场景的 `step`）和对战的规则相同。网络赢时 `success` 是 true。

`input` 给出第 0 方看到的 572 位，全图可见。前 567 位是 7 个通道，每个通道 81 位（每格 1 位，按行排列）：砖墙、钢墙、水、我方基地、敌方基地、我方坦克、敌方坦克。然后是 5 位：我方上一步开过火、敌方上一步开过火、我方还有 2 条命、敌方还有 2 条命、偏置。

参数模块“参数”有回合步数、教师的难度、对战机器人的难度和对战机器人的随机动作概率（0.1）。两个难度的默认值都是 3（困难）。

#### 机器人的 3 档难度

机器人的规则是场景里的 `good(state, k, level)`。它给出第 k 方在这一步同样好的动作。`level` 是难度：1 简单，2 中等，3 困难。每一档按这个顺序判断，用第一条给出动作的规则：

1. 赢：开火能打到对方的基地时，开火。
2. 打坦克：开火能打到对方的坦克时，开火。
3. 挖：站在对方基地的线上（从基地出发、到钢墙或地图边以前的格），朝基地的第一格是砖墙时，开火打掉它。
4. 走：沿最短路走向最近的瞄准格。路上的下一格是砖墙时，开火打掉它。
5. 都不行时等待。

机器人从不朝自己基地的线开火，也不从这条线上的砖墙走。每一档在上一档的规则以外再加规则：

- 简单：只追坦克。瞄准格是能直接打到对方坦克的格。它不看危险。
- 中等：进攻。瞄准格是能挖到对方基地的格。对方下一步能开火时，对方射线上的格不安全。它不走进不安全的格。站在不安全的格里时，它先躲：走到安全的格，或者朝对方开火（对方也开火时，两发对射抵消）。它比较两方走到能挖对方基地的格要几步。对方的步数更少时，它防守：瞄准格是能打到对方坦克的格，并且不挖。
- 困难：它按真正要花的步数算路。走进砖墙算 2 步（先开火打掉它，再走进去）。在一格挖到对方基地，中间每有一格砖墙，多 2 步（开火，再冷却 1 步）。所以它选更快的路和更快的线，两方的步数也比得更准。另外，对方下一步能直接打到我方基地时，它走进对方和基地之间挡住炮弹。已经挡在中间时，它不躲开，而是朝对方开火，不能开火时等待。

机器人 `bot(state, 1, level)` 在同样好的动作里随机选一个。然后它按随机动作概率改做一个随机动作。随机数用回合种子、步数和这一方。

3 档机器人在种子 1 到 200 上对打的结果（训练用的规则）。两方都没有随机动作。每格是第 0 方赢 / 输的比例：

| 第 0 方 \ 第 1 方 | 简单 | 中等 | 困难 |
| --- | --- | --- | --- |
| 简单 | 0.31 / 0.36 | 0.27 / 0.61 | 0.235 / 0.61 |
| 中等 | 0.565 / 0.315 | 0.36 / 0.37 | 0.29 / 0.47 |
| 困难 | 0.525 / 0.285 | 0.455 / 0.29 | 0.33 / 0.375 |

每一行从左到右，第 0 方输得越来越多。在中等和困难两列，从上到下，第 0 方赢得越来越多。对简单时，困难赢得比中等少一点，但也输得更少。其余的局是平局。很多平局走满 100 步：两辆坦克隔着通道里的砖墙等，因为先打掉砖墙的一方会被对方打中。困难的主要优势是算路更准，挡炮弹的规则很少触发。也试过这些办法，都没有让困难变强：一步的同时行动搜索（双方各 9 个动作，按最坏的结果选）、步数一样时也防守、躲的时候不对射。

#### 阶段 1 · 模仿

教师 `teacher(state)` 是场景导出的函数。它给出第 0 方 9 个动作槽的目标位：`good(state, 0, 教师的难度)` 里同样好的动作都是 1。

阶段 1 · 模仿有“中”和“大”两个训练模块。每个框里有一个训练器和一个回路框：

- “中”是 FF 572→32→32→9。
- “大”是 FF 572→128→128→128→9。

两个网络都用 `dense-policy` 和 int16 权重。argmax 读出把 9 个槽映射到动作 0 到 8。两个训练器的方法都是交叉熵，目标是场景的 `teacher`，exploration 是 0.1。训练器没有接指标，所以它保留验证种子上贪心准确率最高的模型。两个训练器的其他配置不同：

- “中”：5000 轮，每轮 16 局，lr 0.005。
- “大”：2500 轮，每轮 16 局，lr 0.003。

每个结构有自己的候选、评估器、评估报告、执行实例和回放。评估器的奖励是场景的 `agreement(transition)`：网络的动作在教师的目标位里时是 1，否则是 0。所以一局的回报是和教师一致的步数。评估器在 256 个固定的测试种子上报告 5 个指标：和教师一致的比例（回报除以步数）、胜率、击毁对方坦克的比例、我方坦克被击中的比例和平局的比例。击毁和被击中的比例数的是至少被击毁一次的局。

回放视图画出地图（砖墙、钢墙、水、两个基地）和两辆坦克。坦克下面的小点是剩下的命。地图来自状态里的 `cells`，所以打掉的砖墙不再画出。基地被毁时画成灰色并打叉。图下面是步数、双方的动作、双方的命和结果。拖动视图里的回看滑条，可以一步一步地看一局。

执行实例走一步时，回放播这一步的动画。坦克先行动，所以坦克在前半步滑一格。炮弹在后半步沿 `trails` 匀速飞到打到的格。砖墙和基地在炮弹打到时才消失。炮弹停下的地方有一个短的效果：砖墙碎掉、钢墙上的火花、坦克或基地爆炸，或者对射的闪光。被击中的坦克在炮弹打到时消失，还有命时它在出发格出现。

一步动画的时长是最近 4 步到达间隔的平均，限制在 80 到 600 毫秒。间隔大于 600 毫秒时（例如单步），时长是 200 毫秒。上一步还没有播完时新的一步到达，上一步在 40 毫秒内播完，然后播新的一步。所以显示可能落后于计算，但不跳过炮弹。等着播的步超过 8 步时，每步只播一帧。拖动回看滑条时，回放直接跳到选中的那一步，不播动画。

场景、参数、奖励参数、种子分区和 5 个指标只有一份。它们在训练模块的框外面，接到所有回路、训练器和评估器上。所以只有场景里有一份规则。每个框在槽位里列出它用的共用模块，例如“场景 · 场景”。每个回路框写着 `ƒ scenario ← 场景`。

#### 阶段 2 · 对战训练

阶段 2 · 对战训练也有“中”和“大”两个训练模块，在阶段 1 的右边。每个框里有一个训练器和一个回路框。网络的结构和回路都和阶段 1 相同。两个训练器的方法都是 REINFORCE。

训练器的 2 个输入把两个阶段连起来：

- `init` 接阶段 1 同一结构的候选的 `weights`。训练从阶段 1 接受的权重开始，不做偏置校准。
- `gate` 接阶段 1 同一结构的评估器的报告。条件是 `{ metric: 和教师一致的比例, min: 0.7 }`。地图每局随机，所以阶段 1 的“中”只到 0.75 左右，“大”到 0.86 左右（测试分区的 256 局）。没有报告、报告已过时或者没有达标时，训练器不开始，并说明原因。

奖励在单独的参数模块“奖励参数”里。所以改奖励不改变阶段 1 的训练快照，阶段 1 的产物仍然兼容：

- 赢的奖励：1。
- 输的奖励：−1。
- 击毁对方坦克一次的奖励：0.3。
- 我方坦克被击毁一次的奖励：−0.3。
- 每步的代价：0.002。

奖励是场景导出的 `reward(transition)`：赢得“赢的奖励”，输得“输的奖励”，平局得 0。机器人的坦克被击中的那一步，再得“击毁对方坦克一次的奖励”。我方坦克被击中的那一步，再得“我方坦克被击毁一次的奖励”。每一步还减“每步的代价”，所以赢得越快，回报越高。

两个训练器的配置相同：2400 轮，每轮 32 局，lr 0.001，entropy 0.01，`gamma` 1。训练器没有接指标，所以它按验证种子上的平均回报选模型。评估器接奖励和 4 个指标：胜率、击毁对方坦克的比例、我方坦克被击中的比例和平局的比例。

训练的顺序：

1. 在“训练器（中）”里点“开始训练”。
2. 训练结束后，在“候选（中）”里点一个候选的“接受”。
3. 在“评估器（中）”里点“评估”。
4. “训练器（中，阶段 2）”的 gate 显示“已通过”以后，在这个训练器里点“开始训练”。
5. 训练结束后，在“候选（中，阶段 2）”里点一个候选的“接受”。
6. 在“评估器（中，阶段 2）”里点“评估”。
7. 对“大”的 6 个模块做同样的步骤。

在 200 个测试种子上和困难机器人打的结果（node，训练器种子 1，训练用的规则）。随机动作概率是机器人的，网络没有随机动作。胜率一列是赢 / 输 / 平局的比例：

| 网络 | 耗时 | 和教师一致的比例 | 随机动作概率 0.1 | 随机动作概率 0 |
| --- | --- | --- | --- | --- |
| 只等待 | | | 0 / 1 / 0 | 0 / 1 / 0 |
| 中，阶段 1 | 1951 秒 | 0.763 | 0.39 / 0.54 / 0.07 | 0.185 / 0.58 / 0.235 |
| 大，阶段 1 | 1082 秒 | 0.868 | 0.525 / 0.4 / 0.075 | 0.2 / 0.49 / 0.31 |
| 中，阶段 2 | 874 秒 | 0.714 | 0.435 / 0.515 / 0.05 | 0.23 / 0.69 / 0.08 |
| 大，阶段 2 | 1164 秒 | 0.691 | 0.58 / 0.365 / 0.055 | 0.32 / 0.54 / 0.14 |

- 只等待时，困难机器人在每一局里都赢。
- 地图每局随机，所以网络要在没见过的地图上打。“大”比“中”强：阶段 1 和教师一致得更多，两个阶段都赢得更多、输得更少。
- 阶段 2 让两个网络的胜率都提高了。机器人有随机动作时，“中”从 0.39 到 0.435，“大”从 0.525 到 0.58。机器人没有随机动作时，“中”从 0.185 到 0.23，“大”从 0.2 到 0.32。两个网络对困难机器人都还是输得多，这里还有进步的空间。
- 阶段 2 的网络和教师一致得更少，因为它们不再只模仿教师。
- 耗时是 node 里测的，同时运行 2 个训练。浏览器里的耗时随机器不同。困难的教师和机器人要算更多的路，所以一步比中等慢一倍左右。

#### 对战

对战有两个冻结的网络“中（对战）”和“大（对战）”，结构和训练模块里的相同。它们的 `weights` 接阶段 2 的候选。训练器正在训练的网络不能被调用，所以对战用单独的网络模块。脚本模块“坦克对战”有 6 个函数输入和 1 个值输入：

- `红方` 和 `蓝方`：两个网络的读出的 `run`。模板里红方是“中”，蓝方是“大”。
- `机器人`：场景导出的 `botMove(state, side, level)`。它给出第 side 方在难度 level 时的动作，按这一方看到的地图。它没有随机动作。
- `battle`、`view` 和 `play`：场景导出的对战函数。
- `设置`：参数模块“对战设置”。它的 `opponent` 选蓝方：0 是网络“大”，1、2、3 是简单、中等、困难机器人。默认是 3，所以默认是红方“中”打困难机器人。

对战的规则也只在场景里，和训练用同一份代码。对战和训练只有这些不同：

- 红方是第 0 方，基地在底部。蓝方是第 1 方，基地在顶部。
- 双方都没有随机动作。训练里的机器人有随机动作。

`view(state, side)` 给出一方看到的 572 位，顺序和 `input` 相同。蓝方看到的地图转 180°，所以每一方的基地都在下方。`play(state, a, b)` 收到每一方按自己的地图选的动作，然后把蓝方的动作换成世界的方向。

脚本有 3 个文件：

- `main.js`：布局和 `main`。每次“重置”开始新的一局，种子就是局号。`main` 在每一局开始时读“设置”，所以改 `opponent` 以后点“重置”，下一局就换了对手。
- `game.js`：一局的流程。每一步，一方是网络时，它先调用 `view` 和这个网络。蓝方是机器人时，它调用 `机器人`。然后它调用 `play`。上一步是对射时，`play` 不用双方的动作，而是让每一方随机移动或者等待一次。随机数来自局的种子，所以同一局的结果可以重复。
- `views.js`：3 个视图。战场画出地图、两个基地、两辆坦克和它们的命。战场和回放一样播每一步的动画，时长的规则也相同。侧栏有 `Controls`、局号、种子、结果和双方的状态：基地、坦克的格、能不能开火和命。蓝方是机器人时，它的名字里有难度，例如“蓝方（困难机器人）”。日志列出每一步双方的动作，`*` 是对射以后的随机一步，最后一行是结果。侧栏和日志直接显示最新的一步。

交换 `红方` 和 `蓝方` 的连线，两个网络就交换位置。

对战的顺序：

1. 在“候选（中，阶段 2）”里接受一个候选。如果“对战设置”的 `opponent` 是 0，也在“候选（大，阶段 2）”里接受一个。
2. 在“坦克对战”里点“运行”。一局结束后，点“重置”开始下一局。

也可以只点一次：点“坦克对战”标题上的 ▶「运行到这里」（ADR 0023）。它从这个模块往上找：

- 候选里已经接受了兼容的产物，就不再训练。
- 没有接受的，就先训练，再接受训练器选出的候选。
- gate 要的报告没有或者过时了，就先评估。

然后脚本重新开始，并运行。状态栏显示每一步。gate 没有通过时，链停下并说明原因。训练模块里的候选、训练器、评估器和执行实例也有这个按钮。

一个无界面脚本在种子 1 到 200 上测了对战。它运行对战脚本的 `game.js` 和页面一侧的调用。网络是阶段 2 的网络（训练器种子 1）。红方是网络、蓝方是机器人时，每格是 200 局里红方赢、输和平局的局数：

| 红方 | 简单 | 中等 | 困难 |
| --- | --- | --- | --- |
| 中 | 79 / 116 / 5 | 56 / 103 / 41 | 54 / 118 / 28 |
| 大 | 74 / 107 / 19 | 72 / 84 / 44 | 67 / 98 / 35 |

每格有 5 到 26 局走满 100 步。其余的平局是两方在同一步都输。“大”对中等和困难机器人赢得更多，输得更少。红方“中”、蓝方“大”时，红方赢 72 局，输 97 局，平局 31 局（23 局走满 100 步）。

`frontend/templates/artifacts/artifacts.test.js` 钉住四位算术和组合器的数字。挖矿、记忆地图和坦克大战没有钉住的数字。场景用 IR 解释执行，代价是训练速度。每步的主要工作见[设计文档第 11 节](design.md#11-正确性与性能)。

`frontend/templates/tank-battle.test.js` 通过运行器和脚本模块的调用检查规则。规则的检查：

- 每一局的地图由种子决定：固定的部分不变，随机的部分左右对称、转 180° 不变，四分之一里最多 2 格钢墙或水，每一格空地和砖墙都走得到。每辆坦克在种子选的出发格，有 2 条命。蓝方看到的位和转过来的对战里红方看到的位相同。双方的规则对称。
- 走进砖墙、钢墙、水、地图外或者坦克的格是等待。两辆坦克可以走进同一个空格并重叠，重叠的坦克打不到对方。
- 炮弹打到第一格不是空地也不是水的格：打掉砖墙或基地，钢墙不变，飞过水。冷却时开火是等待。先移动再开火，所以这一步走出射线的坦克没有被击中。
- 对射时两发都抵消，两方都不算开过火。下一步每一方随机移动或者等待，不用自己的动作，不同的种子给出不同的随机一步。只有一方打到时，它击中对方。
- 被击中少 1 条命，坦克回到出发格。第二次被击中、基地被毁或者步数用完时，对战结束。打掉自己的基地算输，同一步双方都输是平局。
- 每发炮弹的轨迹和规则的结果一致：砖墙、钢墙或地图边、基地、坦克、对射。
- 一局通过脚本的调用跑完，结果和直接调用场景函数、直接运行网络的结果相同。
- 交换连线就交换位置。同一个种子的结果可以重复。

教师和机器人的检查：

- 每一档都在能打到对方基地时开火，在对方基地的线上挖砖墙，不朝自己基地的线开火。
- 中等和困难不走进能开火的对方的射线，站在射线里时躲开或者对射。简单会走进去。
- 简单只追坦克。中等和困难进攻对方的基地，对方离我方基地更近时去拦它。
- 困难把砖墙和挖基地的冷却算进步数：中等觉得两条路一样近时，困难只走真正更快的一条。
- 困难挡住对方对我方基地的直接射击，并且守在中间。中等不挡。
- 每一档的机器人在转过来的地图上给出的动作，都在同一档教师的目标位里。蓝方是机器人时，它在脚本里的每个动作也在同一档教师的目标位里。

训练的检查：

- 两个阶段的回路是同一个环境。阶段 2 的训练器的 `init` 接阶段 1 同一结构的候选，`gate` 接阶段 1 同一结构的评估器。和教师一致的比例是 0.84 时 gate 不通过，0.85 时通过。没有报告或者报告已过时，gate 也不通过。
- 改奖励参数不改变阶段 1 的训练快照的环境。
- 训练的一步里，机器人按参数里的难度行动。网络赢时 `success` 是 true，输和平局时不是。网络只等待时，机器人赢。同一个种子给出同样的随机动作。
- 奖励按结果给赢、输或 0，按这一步的击中给击毁和被击毁的奖励，每一步减每步的代价。
- 和教师一致的比例是网络的动作在教师的目标位里的步数的比例。另外 4 个指标按最后的状态算。

### 哪些是训练出来的，哪些是设计的

| 组件 | 性质 | 证据 |
|---|---|---|
| ADD4 / SUB4 / MUL4 模块 | 训练出来的阈值神经网络（8→12→5、8→16→5、8→112→8）。QAT，int8 权重，每层一个 scale | 穷举 256 组，100% |
| 组合器的策略 | 学出来的：一个工具层的决策头是 11 → 3 个选择 + 8 个数据位。这个工具层用 REINFORCE 学会选哪个工具、交给它哪些位。工具权重冻结。奖励只看答案 | 模板 `arithmetic-combiner`。154 道测试题全对，每题都选对工具，交出 a‖b |
| 工具层与位线 | 设计的：工具层每一步只运行选中的工具。结果零扩展后交给后面的层，或作为输出。位线切片、拼接位向量 | `frontend/core/loop.js`、`frontend/runtime/dense-policy.js`，模块种类 `network` / `bits` |
| 挖矿 / 记忆策略 | 学出来的：挖矿 FF 185→32→7 用 REINFORCE 训练，记忆地图 LIF 55→32→7 用交叉熵训练。两个都是整数网络 | 用户在画布上训练，没有内置产物。每次训练生成新候选 |
| 场景规则 | 设计的：模板里的场景模块和其他代码模块 | `frontend/templates/*.yaml` |
| 链上部署按钮 | 本地 Anvil 上实际点击部署、核对、step、reset。公共链签名没有验证 | 真实回执、事件摘要和持久电位，与本地整数结果逐项核对 |

模块不可改。要优化一个模块，就训练一个新模块。每个模块在它自己的输入空间上穷举检查，这保证组合的正确性。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `?preset=…` 没有放置示例 | 画布不空。`preset` 只在空画布上生效 | 在「文件」抽屉里点「清空整个工作区」，然后重新打开地址。也可以在「添加 → 示例」里放置 |
| 顶栏显示「Python 工作区未连接」 | Workspace 没有运行 | 浏览器训练不受影响。要用 Python 训练，按[第 6 节](#6-用-python-训练)启动 Workspace |
| 开发服务器的地址不是 5173 | 5173 已被占用，Vite 换了一个端口 | 用终端显示的地址。工作区按地址分开保存 |
| 页面空白或报模块错误 | 用 `http.server` 或 `file://` 打开了源码 | 用 `npm run dev`，或者打开构建后的 `frontend/dist/neurom-studio.html` |
| 打开页面时出现冲突面板 | 本地保存的工作区无法恢复 | 先点「导出本地存档」。然后打开改好的文件，或者丢弃本地存档 |
| 执行实例或评估器说网络没有已接受的权重 | 挖矿和记忆地图没有内置产物 | 先训练，再在候选上点「接受」 |
| 候选标为“环境不同” | 训练后改了场景、`budget` 或分区的回合种类 | 重新训练 |
| 链上部署在测试网或主网上不能用 | 这两个网络还没有官方 Factory | 用 Local dev（Anvil） |
| Local dev 核对失败或找不到 Factory | 新启动的 Anvil 上还没有部署协议合约 | 按[第 7 节](#7-部署到本地链)第 2 步运行 `Deploy.s.sol` |
