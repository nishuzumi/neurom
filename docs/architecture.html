1一页总览

Neurom 是一个工作台，用来训练整数神经模块、组合这些模块，并把它们部署到 Monad 链上。画布上的模块图是唯一的真相。训练、评估和执行都用同一个回路执行器。浏览器和 Python 是两个后端，用同一套整数语义。接受的产物按“一个产物一个模块合约”部署。链上计算由不可变的引擎版本完成。

2用户路径

用户路径是一条直线：放模板、改规则、训练、接受候选、评估或执行、部署、核对，然后逐步运行。每一步只把不可变的数据交给下一步。

  1. 放模板从“添加”抽屉放一个训练模块。可选的模板有：挖矿、记忆地图、四位算术和组合器。放下的模块是模板的复制，以后不跟随模板更新（ADR 0003）。frontend/templates/*.yaml、core/template.js
  2. 改规则修改这些部分：参数、场景模块的 init / input / step、奖励或目标、网络结构（层、weightBits）。如果调用线的签名不符，画布不让你连这根线。类型错误会定位到行。
  3. 训练训练器沿输入收集 neurom-bundle，然后交给浏览器 Worker 或 Python Workspace。后端在整条回路上训练一个网络。训练完成时只产生候选。core/sessions/trainer.js
  4. 接受候选工作台按环境、被训练网络的结构和读出检查候选是否兼容。在候选模块里点“接受”。然后这个候选成为这个网络的权重。接受不部署，也不发交易。
  5. 得到产物产物 neurom-module = 快照 + 整数模型 + 来源 + 评估。产物按内容 hash 命名，冻结后不可改。
  6. 评估或执行评估器在测试分区上贪心运行整条回路，并输出报告。执行实例逐步运行，显示每一步每个模块的值和工具调用。视图只负责画。
  7. 部署链上部署模块把一个产物交给官方 Factory。如果网络有工具层，先部署工具。相同内容的权重块只创建一次。
  8. 核对verifyModule 查 isModule、描述符、引擎版本、形状、权重块地址，再递归核对每个工具。
  9. step / reset每一步先在本地做整数执行。然后把结果和链上返回的这些值逐项比对：scores、action、counts、voltages、Stepped 事件和 stateOf。

如果之后再改画布，旧的运行、报告和产物不变。但是工作台把它们标成过期，因为它们钉住的快照和画布现在的内容不同。

3画布与模块图

ModuleGraph 是唯一的可执行图。组合、回路框、训练模块框都只是这张平面图的视图。没有第二份子图。工作台在连线时当场校验，不合法的连接连不上。

图里有什么

  • 模块：每个模块都属于一个模块种类。配置先合并默认值，再按 schema 校验（registry.js 的 validateConfig）。
  • 值线：把输出值交给输入，消费方求值时读取。值线可以接记录的单个字段，例如 params.steps。
  • 调用线：把函数交给调用端口，按签名检查。函数名不决定角色，接到的端口才决定角色。
  • 回路输入：只有回路的 action 和网络的 weights。只有它们能让值线闭环。图拒绝所有其他的环。调用线不能递归。

连一根线时发生什么

ModuleGraph.connect 依次检查这些项：端点、线的种类、句柄、单一来源、类型可赋值和环。然后它临时装上这根线，运行一次 resolve。如果出现新的问题（“未完成”类问题除外），它回滚这根线。

resolve.js 做不动点迭代。它先取各种类的 ports，再反复调用 infer 推出输出类型，最多 24 轮。然后它检查每根线、必填输入和种类自己的 problems。它还把类型化的调用登记进 Resolution.calls。

值类型：number、boolean、string、vector、array、record、table、handle。位向量最宽 65535（core/types.js 的 MAX_BITS，ADR 0021）。

模板与预制

模板是 YAML（neurom-template），记录模块、配置、连线、暴露端口和组合。parseTemplate 用注册表和图规则校验模板。实例化就是复制。

预制模块是带 prefab 记录的组合。这份记录有两部分：槽位（例如“场景”接 loop.scenario，“目标”接 trainer.objective）和期望连线。工作台列出缺少的期望连线，你可以点“恢复”。这份记录只用于呈现。运行时只读真实连线（core/prefab.js）。

4程序 IR 与场景

任务规则全是数据。代码模块里的受限 JavaScript 编译成同一种 IR（neurom-program）。浏览器和 Python 按同一套规则执行这种 IR。应用代码里没有任何任务专属的 JS、Python 或 Vue（ADR 0004）。

代码模块是一份文件

ADR 0005 定义了代码模块，ADR 0012 补充了角色合约。规则如下：

  • inputs 里的每个名字是一个代码输入。代码输入是必填的值输入端口，在整份文件里可读。它作为静态值绑进读它的函数和常量。
  • export const 是值输出，每个快照只算一次。
  • export function 是调用输出。接到的端口决定它的角色，例如奖励、目标或指标。
  • module 输出把整份文件交给按角色调用它的种类，例如回路的 scenario。
  • 不导出的函数是辅助函数，在调用处内联。不允许类型语法。类型来自调用方和连线。

实现自己决定参数名。消费方种类的角色合约固定参数个数、类型和返回值。代码编辑器为每个角色开一个角色页。角色页锁定协议头，并用第一个回合运行一次示例。

5回路与训练

训练、评估、执行共用一个场景协议和一个回路执行器（ADR 0009）。训练只更新一个网络。回路里的其他网络用已接受的权重冻结运行。这叫整回路训练。

回路体与快照

  • 回路体 = 从 loop.input 到 loop.action 的值路径上的所有模块，只能是网络、读出、位线。外面接进来的静态值（网络的 weights、读出的 actions）和工具不算回路体。
  • buildBundle（core/bundle.js）把回路体冻结成 neurom-bundle。快照有三部分：env、loop 和驱动自己的部分。env 包含场景程序及绑定值、budget、actions、类型、回合类型和表。loop 包含回路体节点，其中冻结网络带已接受模型，被训练网络留空。驱动自己的部分包含目标、指标、分区和配方。
  • envHash 单独标识环境。快照按内容 hash 命名，所以之后的画布修改不影响它。

6网络与量化

只有两种整数引擎：dense-policy（FF / LIF，可带工具层）和 threshold-layers（无状态阈值网络）。权重默认 int8，可选 int16。训练器为每个区域自己选 scale 和移位 k。偏置总是 int16（ADR 0015）。

FF：每层一个 tick。LIF：每段运行满 ticks（1..64）。每个 tick 计算 V = V − (V >> leak_shift) + I（leak_shift 0..10，算术右移）。如果 V ≥ 该层阈值，计一次放电，并把 V 置为 reset（int16）。LIF 输出层的偏置乘以 ticks。电位是 int32，溢出时 JS 抛错、链上回滚，两边一致。

LIF 电位不是模型数据。它属于每个执行器会话，并且要显式重置。

量化：每个区域自己定

  • 区域 = 一个仿射映射。下面每一项各是一个区域：普通层、输出层、工具层的选择头和数据头、阈值网络的每个映射。
  • weightBits 是 8（默认）或 16，Q 是 127 或 32767。scale = Q / max|w|（全零时取 Q），所以权重不应被截断。
  • 移位 k 取能让偏置和 LIF 阈值装进范围的最大值，范围 0..20（frontend/training/quantize.js，MAX_SHIFT = 20）。
  • 偏置和阈值 th 都是 int16，单位比权重细 2^k。LIF 阈值的范围是 1..2^31−1。
  • scale 只是元数据。真正的整数语义是 W 码值、b / th 和 k。没有全网统一的 scale。
  • 内置模板的选择：挖矿用 int8。记忆地图用 16（weightBits: 16）。不支持 int4 和 fp4（ADR 0015）。

7工具层与嵌套

工具层是稠密网络层列表里的一项。每一步，工具层只选一个工具，只运行这个工具，然后把结果拼回去继续计算。任何官方网络都能当工具。工具的状态放在调用方的会话里。工具最多嵌套 3 层（ADR 0010、0014）。

一步里发生什么

  1. 决策头决策头在前一层上算出 K 个选择 logit 和 D 个数据 logit。选择取第一个最大值。数据位 = logit > 0。
  2. 只调用被选中的工具把数据位的前 inputs 位交给它。没被选中的工具不运行，状态不变。
  3. 拼接结果零扩展到 R 位。结果 ‖ 前一层交给下一层。如果工具层是最后一层，这 R 位就是网络输出（score 为 +1 / −1）。

有工具层时，回路的 Transition 多一个 loop 字段。这个字段为每个带工具层的网络的每个工具端口记录 {choice, data, result}。所以同一回路里的网络标题必须唯一。

什么能当工具

  • 代码工具：代码模块导出的 (bits) → bits 函数，无状态。代码工具只在浏览器 / Python 里运行，不能部署。
  • 网络工具：冻结网络经位模式读出的 run。网络工具可以是 FF、LIF，或自己也带工具层的网络。在链上，网络工具必须是同一官方 Factory 的模块。
  • 阈值网络可以当工具，但不能宿主工具层。工具层的宿主必须是稠密网络，并用 REINFORCE 训练。

状态放在调用方会话里

选择器自己的 LIF 电位在最前面。后面依次是每个工具的状态，先按工具层排序，再按连线顺序排序。如果工具自己带工具，内层工具的状态嵌套在这个工具的状态里。整块合计 ≤ 256 个 int32。链上把 8 个 int32 打包成一个 storage word，所以最多 32 个 word。

工具状态随调用方会话重置。工具状态只在工具被选中的那一步前进。如果一个 LIF 网络被当作工具，它用调用方会话里的那一片状态。它不用自己作为独立模块时的会话。

为什么是 3 层

每个网络至多有 8 个工具层。一步只递归地运行选中的工具。所以一步至多有 Σi=1..d 8i 次工具调用：d = 3 时 584 次，d = 4 时 4,680 次。按 Monad 规则，每多一层调用约多 24k gas。3 层时只这一项约 14M，在单笔 30M 以内。4 层时约 112M，放不进任何交易 估算（ModuleFactory.sol 注释、contracts/README.md）。

如果嵌套超过 3 层，画布把它报告为网络的问题。链上 Factory 以 depth 拒绝部署（MAX_TOOL_DEPTH = 3）。

实测数据 实测：2 位的小选择器选 LIF 工具时，一步用 47,013 gas。选 FF 工具时，一步用 41,058 gas（Modules.t.sol testGasOfNetworkTools）。调用者只为被选中的工具付 gas。

所有持久数据都在一个 Workspace 里。工作台自动把它存到浏览器 localStorage。如果存档读不进来，工作台不覆盖它，而是打开冲突面板（ADR 0008）。工作台从不改写产物。

  • 改动后 300 ms 防抖写入 localStorage，键名 neurom-workbench（graph_app.js 的 persist / saveWorkspace）。产物按内容 id 存进 IndexedDB 的 neurom-artifacts（core/local-save.js）。存档只用 artifactIds 记下 IndexedDB 里已经有的产物，其余的产物仍写在存档里，所以存档不会引用不存在的产物。写入是同步的，关页面时也一样。IndexedDB 里的产物不自动删除，因为所有标签页共用它们。没有 artifactIds 的旧存档照常打开。浏览器没有 IndexedDB 时，存档照旧写入全部产物。

  • 如果另一个标签页存了不同内容，本页不默默接受，也不覆盖。本页显示提示：“载入”用对方的内容，“用本页覆盖”写回本页的内容。
  • Python 训练的运行另外存在 Workspace 服务自己的运行目录里（training/workspace.py），所以浏览器刷新后还能重新挂上。

冲突面板（ADR 0008）

  1. 读不进来如果本地存档不是 JSON、格式标签不对或校验失败，工作台打开冲突面板。面板显示找到的格式、出错位置和原因。
  2. 暂停一切写入面板打开时，工作台不自动保存，不执行“用本页覆盖”，也不回应其他标签页。
  3. 你来选选择一个操作：导出本地存档，打开改好的文件替换它，或者二次确认后丢弃它。工作台按同样的严格校验读取打开的文件。如果打开的文件读不进来，工作台只报错，不改当前工作区。

工作台从不改写产物。链上模块的 artifactId 是产物的内容 hash。如果产物被改写，核对就会失败。

9链上架构

一个产物部署成一个模块合约。模块合约很小。它的身份写在代码里，权重放在不可变的权重块里。计算交给它终身绑定的引擎版本（用 STATICCALL，引擎写不了任何东西）。可变的只有每个 (actor, session) 的状态和 owner。

部署：通常一笔交易

  1. 本地准备deploymentOf(artifact) 校验产物，并计算形状（dense 4 个词，阈值 2 个词）。然后它把权重编码成按列的字节，切成 ≤ 114,688 字节的块。每块的 id = keccak256(数据)。frontend/module-chain.js
  2. 先部署工具如果网络有工具层，部署桥递归处理每个工具。如果同一官方 Factory 里已有同一产物的模块，并且核对通过，部署桥复用这个模块。否则部署桥先部署这个工具。代码工具不能部署。
  3. 只读规划按 CREATE2 公式算出每个权重块的地址。查出链上已有哪些块。估算 gas。
  4. 预检checkDeploy(spec, data) 运行和部署完全相同的检查，但什么都不创建。所以被拒绝的模块不花任何交易。
  5. 发交易deploy(spec, data) 在一笔交易里创建缺少的权重块和克隆，并初始化 owner。这笔交易要么全部成功，要么全部失败。gas 上限 = 估算 + 10%。
  6. 放不下就拆如果估算 + 10% 超过 30M，先用 createChunk 创建缺少的块，每笔交易一块。部署桥一直这样做，直到剩下的块和模块装得进最后一笔交易。如果单独一块也放不下，部署桥明确报错。
  7. 可续传块地址只由 Factory 和内容决定。如果部署中断，重新规划，然后从缺少的块继续。已有的块不重发。

deploy 的检查在 ModuleFactory._check 里。如果 version 为 0，它用该引擎 id 的最新版本，否则 version 必须是该引擎 id 列出的版本。端口宽度是 1..65535。工具必须是本 Factory 的模块，深度 ≤ 3。引擎的 check 必须接受形状，状态宽度 ≤ 256。权重块地址和总字节数必须与形状一致，身份必须装得进克隆。

一步：模块 → 引擎版本 → 权重块

  1. 调用调用者对模块调用 step(session, input)。键 = keccak256(abi.encode(msg.sender, session))，所以谁也写不了别人的状态。会话标签经 keccak256 变成 session。
  2. 委托克隆把 calldata 加上自己的身份，DELEGATECALL 给 NeuromModule 实现。
  3. 只读计算实现读出打包的 int32 状态，然后 STATICCALL 引擎版本的 run(kind, inputs, outputs, shape, chunks, tools, state, input)。引擎用 EXTCODECOPY 读权重块，只对选中的工具调用 forwardFrom。
  4. 写回引擎返回 (scores, action, counts, voltages)。只有模块把 voltages 写回存储，并发出 Stepped(actor, session, keccak256(结果))。reset 清零这个键。

只读入口：forward（从静息状态）、peek（现有会话只读预测）、peekAs / stateOf（读任一 actor）、forwardFrom（给定打包状态，不读写存储）。只有 step 和 reset 改状态。

协议角色与交接

  • ADMIN：授予 / 撤销两种角色，addVersion、setLatest。
  • UPGRADER：只能 upgradeToAndCall 升级 Factory 代理。
  • 部署者起初有两种角色。交接没有“提名-接受”步骤，而是授予 → 核对 → 撤销。在确认多签能用之前，绝不撤销（script/HandOverRoles.s.sol）。
  • 撤销最后一个 ADMIN 不可挽回。之后再也没有人能管理角色和版本。
  • Roles 不存持有者列表。contracts/scripts/list-roles.mjs 读 RoleGranted 事件，再用 hasRole 逐个确认。
  • 模块的 owner 不是协议角色。owner 只是收款身份，用两步转让（nominateOwner / acceptOwnership）。模块本身不存钱。

引擎版本的规则（ADR 0017）

  • 每个版本是一个不可变合约。版本只能增加，不能修改或删除。一个地址只能属于一个引擎 id。
  • 部署默认用最新版，也可以指定一个已列出的版本。模块身份里写死版本地址，终身不变。owner 和协议都改不了它。
  • 同一 id 的所有版本必须逐位算得一样。改数值就要用新的引擎 id。
  • 链上只检查“有代码、没登记过”。等价性靠加版本之前的离线核对。contracts/scripts/engine-version-check.mjs 在分叉上用 anvil_setCode 换上候选代码。然后它比较每个决策的 scores、action、counts 和下一状态。只有 0 差异时，它才打印 addVersion / setLatest 两笔交易。它从不广播交易。
  • 本地核对 dense-policy 有 19 个用例、480 个决策（contracts/README.md）。
  • 坏版本影响不了已部署的模块。但是在 ADMIN 把最新版设回去之前，新部署会用坏版本。工作台显示每个模块用第几个版本，以及这个版本是不是最新。

10信任与防复制

权重是公开的。没有办法阻止复制，也没有办法认出复制品。所以信任只建立在“谁创建了这个模块”上，也就是官方 Factory 加不可变的引擎版本。挖矿游戏的规则（ADR 0018）让复制品拿不到纪录，不靠链上检测。

为什么认不出复制品

  • 权重块是代码，任何人都能 getCode 读出来。
  • 改权重可以不改行为。例如打乱隐藏神经元的顺序，hash 全变，行为不变。

协议密钥能做什么、不能做什么

能不能
加引擎版本、设最新版：影响之后的新部署（ADMIN）改已部署模块的计算、引擎版本、权重或身份
升级 Factory 代理（UPGRADER）。理论上，新实现可以把任意地址标成模块写模块的状态（只有模块自己写，键里带 msg.sender）
授予、撤销协议角色（ADMIN）拿走资金：模块不存钱，引擎在 STATICCALL 下写不了任何东西

所以付钱的合约（挖矿游戏）不能只信 isModule。它还必须检查两件事：模块是模块实现的克隆，并且模块运行的是它接受的引擎版本（ADR 0016、0017）。

只认官方 Factory 是工作台的规则，不是链的规则。合约用 MIT 许可，谁都可以部署自己的 Factory，并在工作台之外使用。工作台只是不认这样的 Factory。

挖矿游戏的规则 未完成

下面是 ADR 0018 已定的规则。收益（基础收益、首创溢价、挑战期）先搁置。合约还没写（见 §15）。

  • 纪录：纪录归最先达到最好成绩的模块。新模块必须超过纪录 δ 才能夺走纪录。
  • 两步评分：破纪录时先登记。然后用 k 个区块之后的随机数运行一批回合。如果登记了但不评分，这次就算失败。
  • 暗桩挑战：如果暗桩作者在新保持者部署之前提交过承诺，作者可以揭示暗桩。如果命中 ≥ 40 / 64，游戏撤销纪录，封禁模块，纪录回到上一个有效保持者。
  • 难度递增：难度按累计挖出总量升级（更大的图、更少的矿）。每笔交易一张小地图，种子是 hash(prevrandao, 玩家, 计数器)。
  • 蒸馏一个复制品再用真训练超过 δ，是正当竞争。

值线Value Wire把输出值交给输入，消费方求值时读取。一个输出可以接多个输入。
回路输入Loop Input下一步才生效的值输入，允许值线闭环。只有回路的 action 和网络的 weights 是回路输入。
调用线Call Wire把函数交给消费方，消费方可以调用任意次。连接时按签名检查。
位线Bit Wire切片、拼接位向量的模块，本身不是线。
代码模块Code Module持有一份受限 JS 文件，导出就是输出端口。
代码输入Code Input代码模块 inputs 里的一个名字：必填值输入，整份文件可读的静态值。
注释Doc Comment导出函数上方的 JSDoc 文本，随端口传播。工作台忽略里面的类型。
角色Role某个模块按协议调用的导出。消费方种类规定参数个数、类型、时机和含义。
角色页Role Tab代码编辑器里一个角色的标签页，协议头锁定，带帮助和示例运行。
程序Program一个导出函数或顶层常量编译成的有类型、无环、有界计算。浏览器和 Python 按同样的规则解释它。
参数Params一种模块：声明带范围和默认值的字段，提供取值，还可以有函数输入。
约束表达式Constraint Expression用其他字段当前值写出的范围或选项，例如 max: grid - 1。
函数输入Function Input因声明而存在的调用端口，签名由角色固定，例如 Params 的 options。
回路与场景
回路Loop回合运行器每一步的边界模块：接场景、输出输入位、收回动作。
回路体Loop Body从回路 input 到 action 的值路径上的模块，只能是网络、读出、位线。
回路框Loop Box标成回路视图的组合。它的成员必须与推导出的回路体一致。它不是真相源。
训练模块Training Module展开成一个框的预制模块。左栏放各驱动和环境，右边的子画布放每步计算。
整回路训练Whole-loop Training训练回路里一个网络，其余网络按已接受权重冻结运行。
环境Environment场景程序、预算、动作、类型和回合类型。它们钉在快照的 env 里，由 envHash 命名。环境不是模块。
运行器Runnerreset / input / step 回合协议，JS 和 Python 各实现一次。
锁步运行Lockstep Run一批 Start 一起运行，每回合一条 lane。结束的 lane 不再走步。
场景模块Scenario Modulemodule 接到 loop.scenario 的代码模块，导出运行器调用的角色。
随机数Random提供 32 位 LCG 跳跃表 rng: {mul, add} 的模块。
回合起点Start一个回合的起点记录：种子、枚举组合或时间窗。
回合Episode从 Start 到终止或截断的一次运行，及其摘要。
任务终止Termination场景的 step 返回 done: true。
回合截断Truncation因步数预算用完而结束。截断不同于终止。
状态State场景某一时刻的显式记录。
转移Transition一步的记录 {prev, action, next, done, truncated, success}，有工具层时另带 loop。
输入位Input Bits场景 input 返回的 0/1 位。这是网络唯一能看到的东西。
环境参数Environment Parameters控制初始化、推进、终止的场景输入。它们永远不是网络输入。
感知参数Perception Parameters控制 input 揭示什么的场景输入，例如视野半径。
读出Readout把 scores 变成动作：取最大值查表，或解码成位。
无效动作Invalid Action读出表里标 null 的槽，解码为 −1。它用掉一步，但不改状态。
网络Network把输入位变成整数 scores 的模块。权重来自自己的 artifact 或 weights，不能两者都有。
工具层Tool Layer稠密网络层列表里的 { tools, data? } 一项：选一个工具、给它数据位、拼接结果。
工具Tool接进工具层的 (bits) → bits 函数：代码导出，或冻结网络的读出（位读出或 argmax 读出）的 run。
数据集Dataset导入后按内容 hash 固定的一张表。
分区Partition把回合分成训练 / 验证 / 测试的模块。

学习目标Objective训练器调用的函数：奖励 fn(Transition) 或监督目标 fn(State[, Table])。
奖励Reward学习目标的一种：对一次 Transition 的数值反馈。
训练方法Training MethodREINFORCE、交叉熵、hinge。每种方法要求特定的引擎和读出。
训练后端Training Backend浏览器或 Python。换后端不改模型的执行语义。
训练器Trainer一种驱动：在回路上整回路训练 structure 接的网络，并产生训练运行。
训练运行Training Run在一个快照上的一次训练，连同记录和候选。
训练快照Bundle不可变的 neurom-bundle。如果它与画布不一致，结果是过期（stale）。
候选Candidate训练产生、尚未接受的产物。
模型产物Model Artifact冻结的快照 + 模型参数 + 来源 + 评估，按内容 hash 标识。它不是运行时记忆。
接受Accept把一个产物选为当前权重。接受不部署，也不发交易。
评估器Evaluator一种驱动：用已接受的权重贪心运行一个分区，计算指标，输出报告。
报告Report评估的输出：指标、分区指纹和各网络用的产物。报告可以按轴分组，也可能过期。
执行实例Execution一种驱动：逐步运行整回路，有自己的时钟、电位和历史。
视图View可视化执行或报告的模块，不拥有执行状态。
视图脚本View Script视图自带的 JS，在沙箱里只负责画，不回流到图或快照。
链上部署Deployment把一个产物部署成模块合约并核对的模块。一次部署创建一个独立实例。
引擎版本Engine Version计算一个执行引擎的不可变链上合约。模块终身绑定部署时的版本。
模块合约Module Contract一次部署为一个产物创建的链上实例：身份、权重块、会话状态。
权重块Weight Chunk代码只有产物部分权重的合约，任何人可读，永不改变。
官方 FactoryOfficial Factory工作台在一条链上唯一部署和信任的模块工厂。

挖矿游戏Mining Game唯一调用挖矿模块的应用合约，逐位重现场景（未建）。
