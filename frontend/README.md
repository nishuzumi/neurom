# frontend — 模块工作台

**中文** · [English](README.en.md)

`index.html` 是唯一入口。画布上的一切都是**模块**，例如参数、代码、随机数、回路、网络、读出、位线、训练器、候选、评估器、执行实例、视图和链上部署。每种模块只在代码里实现一次。一个任务是一个**训练模块**：它由若干模块和连线组成，是一份组合模板（YAML 数据文件），不是代码。系统设计见 [docs/design.md](../docs/design.md)。术语见 [CONTEXT.md](../CONTEXT.md)。

画布使用 Vue 3 + TypeScript + Vue Flow。一个宿主节点组件承载所有模块，每种模块有一个内容组件。组合节点承载模板实例和回路框。训练模块节点画展开的预制模块。领域内核（`core/`）、程序解释器（`ir/`）、训练器（`training/`）和整数执行器（`runtime/`）与画布分离。Vite 负责开发与打包，ethers 用于链上交互。

第一次使用时，先读 [使用指南](../docs/user-guide.md)。开发环境、测试矩阵和常见开发任务见 [开发者文档](../docs/development.md)。

## 启动

1. 在仓库根目录运行 `npm ci && npm run dev`。
2. 打开终端显示的地址（默认 `http://localhost:5173/`）。

源码包含 TypeScript 和 Vue SFC，所以不能用 `http.server` 直接服务。开发服务器把 `/api` 代理到本机 `127.0.0.1:18766`。不启动 Python 时，浏览器训练仍可使用。

如果需要 Python 训练，在仓库根目录运行：

```sh
npm ci && npm run build
python3 -m venv ~/.cache/neurom-venv
~/.cache/neurom-venv/bin/python -m pip install -r training/requirements-torch.txt
~/.cache/neurom-venv/bin/python training/workspace.py --port 18766
```

然后打开 **http://127.0.0.1:18766/**。服务提供 `frontend/dist/` 中构建好的单 HTML，并在同一来源提供 `/api`。修改源码后，重新构建，或使用 Vite 开发服务器。不要从其他静态端口或 `file://` 跨域连接训练服务。协议与 AI 接入见 [训练指南](../docs/ai-module-training.md)。

用 `?preset=<模板 id>` 打开空画布时，画布直接放置对应示例。也可以用 `#<模板 id>`。模板 id 例如 `mining-task`、`memory-map-task`、`arithmetic-add4`、`arithmetic-combiner`。这只适用于声明了 `preset` 的内置模板。

## 画布

- 左侧导航栏有三个抽屉：
  - **添加**：示例、组合模板、我的模板、单模块模板、空白模块。
  - **模板**：模板库。
  - **文件**：清空工作区。
- 顶栏的“保存工作区 / 打开”导出和导入整个工作区 JSON。工作台只读取 `neurom-workbench` 文件。有的文件打不开：它不是 JSON、格式标签不同，或者校验不过。这时状态栏显示找到的格式、出错位置（例如 `graph.nodes[2].config`）和原因。当前工作区保持不变。
- 每个模块是一个节点。节点有可改的标题、种类徽标、问题徽标（悬停看原因）、端口带和折叠 / 删除按钮。
  - 拖右下角或四条边来调整大小。节点不画手柄，鼠标移上去时变成调整大小的箭头。用 Tab 聚焦到右下角后，用方向键微调。按住 Shift 时每次 1 像素。按 `Home` 恢复默认大小。
  - 宿主决定宽度，内容随之排布。
  - 没拖出高度时，代码框贴合代码行数。20 行以内按内容高度，超过 20 行在框内滚动。
  - 拖出高度后，内容填满外框。代码框、文字框、视图的网格 / 曲线 / 表格撑满外框。表单类内容不拉伸，空白留在下方。
  - 外框比内容矮时，代码框先缩到 3 行。还不够时，内容在框内滚动：滚轮滚动内容，Ctrl + 滚轮仍缩放画布。内容不会溢出边框。外框最矮是标题和端口带，再加一条内容。
  - 外框是唯一的尺寸控制。框内文本框没有自己的拖拽角，代码框也没有“展开 / 收起”。
- **端口**：输入在左，输出在右，固定在所在行。
  - 驱动模块的 `loop` 与 `structure` 输入例外。它们排在右栏顶部，朝向它们指向的回路框。在训练模块里，它们画成子画布左边的探头（见下文）。
  - 值端口实心。调用端口以 ƒ 标记（斜体）。
  - record 类型的输出默认是一个整体对象。名字左边有 `+`，点开后，下一级字段以树状列在下面。每个字段都能直接拖线。字段本身还是 record 时，它也带一个 `+`，可以继续展开。
  - 同一时间只有一个模块的字段树展开。点击别的模块或空白处，字段树就收起。收起后，只有已经连出去的字段留在模块上，并显示完整路径（例如 `params.steps`、`value.cfg.bonus`）。
  - 必需而未接的端口名后有 `*`。悬停端口显示类型或签名。
- **两种线**：值线是实线，调用线是虚线并带 ƒ。
  - 拖线时，两端的端口决定线的种类。
  - 工作台拒绝以下连线：
    - 类型或签名不符的连线。
    - 成环的连线。只有接进回路的 `action` 与网络的 `weights` 可以闭合回路。
    - 递归调用。
  - 底部状态栏显示拒绝原因，例如“调用线只能连接调用端口”“类型不匹配：需要 report，得到 weights”。
  - 选中线后，按 `Delete` 断开。
- 连线走向：
  - 右上角的“连线设置”选择曲线 / 折线 / 直线和默认颜色。
  - 单根线的右键菜单可以添加和删除中转点、改颜色、断开。
  - Alt+点击或双击线，添加中转点。拖动中转点来移动它。双击中转点来删除它。
  - 中转点只改变画法，随工作区保存。
- 移动：拖模块或组合的标题栏或端口带。端口的圆点本身用来连线。内容区留给控件和选文字。展开的组合框里的空白就是画布。
- 平移有以下方法：
  - 触控板双指滑动，或滚轮。`Shift` + 滚轮横向平移，和 Figma 一样。
  - 中键拖动。
  - 指针在画布上时，按住空格，直接移动鼠标，不用按鼠标键。指针在模块和连线上也可以，不会拖动或选中模块。刚点过的按钮和下拉框不影响这个操作。只有正在文本框里输入时，空格才照常输入。
- 缩放：双指捏合，或 `⌘ / Ctrl` + 滚轮。`F` 全览，`0` 恢复 100%，`+ / −` 缩放。右下角的“选中 / 全览”用来定位。在能滚动的模块内容区里，滚轮先滚动内容。在输入框内，快捷键不生效。
- 多选：左键拖动空白处来框选，展开的组合框内的空白也算。`⌘ / Ctrl / Shift` + 点击加选。`⌘ / Ctrl A` 全选。方向键微移选区。
- 历史与打包：
  - `Ctrl / ⌘ Z` 撤销，`Shift Z` 或 `Y` 重做。
  - `C / V` 复制粘贴。粘贴的模块有新 id，选区内部的连线保留。
  - `G` 把选中的模块打包成组合，`Shift G` 解包。选区里的组合连同成员一起打包，成员不会拆出来。选中的模块分属不同的组合时，工作台拒绝打包。
  - 历史记录图结构、配置、布局与连线外观。历史不回滚训练运行、产物或链上交易。
- **组合**：
  - 折叠时，组合是一个节点，只露出暴露的端口（“成员 · 端口”）。标题旁显示来源模板 `id@revision` 和成员数。
  - 点标题栏右侧的 `+` / `−`（或双击标题）展开或折叠组合。展开后，虚线外框包住成员，成员在原处编辑。
  - 标题栏还有“存为模板”“解包”、⚙ 组合设置（对外端口、回路框）和删除。
  - 把模块拖进展开的组合框，模块就成为成员。把模块整个拖出框外，它就离开组合。选中一个展开的组合时，新建的模块直接放进这个组合。
  - 组合可以嵌套。可执行的图始终是扁平的，连线连在成员端口上。
- **回路框**：标成回路框的组合就是回路本身。它的徽标是“回路”，边框是实线。回路模块不单独画。框在成员周围画出一回合怎么运行。
  - 框的各部分如下：
    - 顶部是 `Start ← loop`。`loop` 句柄在框的左边上，驱动者（训练器、评估器、执行实例）接在这里。后面列出每个驱动者带来的分区和回合数。
    - `Start` 下面是 `ƒ scenario ← 场景`，句柄在框的左边上。
    - 左栏是 `init(start) → State` → `State` → `input(state) → bits[I]`。`init` 是可选的，没导出时写“未导出”。`input` 句柄在它右边，接回路体。
    - 右边是 `action: number`。场景导出 actions 时，这里列出动作名。`action` 句柄在它左边。
    - 下面是 `step(state, action) → { state, done, success }` 和结束条件 `done ∨ t = budget`。
  - 粗线是回路自己的流程。回程标 `¬done ∧ t < budget`，budget 为 1 时画淡。彩色线才是图里的连线。
  - 有执行实例在运行时，State 上显示 `t / budget`。input 下显示这一步的输入位，action 上显示这一步的动作。
  - 框里只写协议签名、从图推出的值和空状态（例如“未连接”“未导出”）。悬停 `场景.init / input / step` 时，显示场景的 JSDoc。点一下跳到代码。
  - 标题栏显示 `budget`。回路框放在训练模块里时，问题显示在训练模块的标题栏上。
  - 折叠时，框多一行回路体摘要，例如“每一步：输入位 → 网络 → 读出 → 动作”。
  - 连线决定回路体，框只是回路体的视图。框里多了或少了模块时，回路报“回路框的成员与回路体不一致”。
- **训练模块**：从带槽位（`slots`）的模板整件实例化的组合是一个**预制模块**。模板里写了 `slots` 的嵌套分组也是预制模块，它外面的模块可以被几个训练模块共用，例如坦克大战的场景。展开时，它画成一个深色框，徽标是“训练模块 · 方法”。标题栏有存为模板、折叠和删除。它是不是训练模块只看这条预制记录，与里面有几个训练器无关。成员增减不会让框消失。
  - 左栏顶部是**槽位**：
    - 模板声明槽位，例如场景、训练集、验证集、目标、指标、评估、执行。每个槽位一枚按钮，按钮排成一行，放不下时换行。
    - 按钮列出接在槽位上的模块。点一下模块，就定位到那一段。
    - 槽位空着时，有「+ 场景」「+ 分区」「+ 奖励」这样的按钮。点按钮后，框里新建模板给的桩模块，并把它接到那个端口。
    - 必需而空着的槽位名字标红。
    - 左栏不止一列时，接到框外的输入占第一列，槽位按钮在其余列里排开。所以槽位只占顶部几行高。
    - 槽位里装的是什么只看真实连线，不另存。
  - 模板里槽位之外的连线是**预期连线**：
    - 预期连线断开，或别的线替换了它时，槽位下面出现一行“缺少 成员.端口 → 成员.端口”和「恢复」。标题栏的问题数也算上它。
    - 「恢复」把占着那个输入的线换回来。这个操作可以撤销。
    - 允许有意改线。执行只看连线，不读预制记录。
  - 槽位下面是训练器和它的附属模块。它们按段落排列，不画卡片。段落的顺序是：
    1. 数据：数据集、分区。
    2. 环境：接到回路 `scenario` 的场景模块，以及只给它的参数和随机数。训练器、评估器、执行实例共用环境。
    3. 目标：奖励或监督目标，以及只给它们的参数。
    4. 指标。
    5. 训练器。
    6. 候选。
    7. 评估器及它的报告视图。
    8. 执行实例及它的视图。
  - 每段有一行段头：种类、标题、问题、折叠、删除。段头下面是模块的内容。段落折叠后只剩段头。
  - 右边是一块下凹的子画布，只放每一步的计算。回路框和不属于左栏的成员（例如冻结网络）都是普通节点。子画布的空白处也是画布。
  - 连线都是图里真实的线，每根都能断开和重连：
    - 左栏模块和子画布里模块之间的线接在子画布左边的**探头**上。探头的圆点骑在边上，标签“成员 · 端口”在圆点上方。
    - 朝向回路的 `loop` / `structure` 输入没接线时，也保留探头。
    - 接到框外的端口和没接线的端口在框的外侧，输入在左，输出在右。
    - 左栏模块之间的线不画。
  - 折叠后，训练模块就是普通的折叠组合。
  - 左栏的分列：
    - 左栏的段落自动分成几列，让整个框接近 1.5 : 1。段落按顺序一列一列往下排。段落运行时变高，只加长所在的列，不换列。
    - 段头左边的种类标签是拖动把手。拖到某列两段之间，段落就放在那里。拖到两列之间的空隙，就新开一列。分列随之保存，此后不自动重排，“整理”也保留它。
    - 拖右下角的手柄，按当前顺序重新分成几列。横向拖动按列宽，纵向拖动按高度。双击手柄恢复自动分列。
    - 点一个段落，左边出现蓝条。再点“选中”，画布就定位到它。参数段的段头也有 ⚙。
    - 模块因为拖放或连线进出左栏时，状态栏写「X 已移到左栏」或「X 已回到画布」。进左栏的那一段自动选中。
- **自动整理**：
  - 整理按连线层次从左到右排列，一层一列。
  - 层数多时，列自动折成几行，像段落换行。每行宽度尽量均衡，整体形状贴近窗口比例。所以整理同时使用横向和纵向空间。
  - 相邻两列都有训练模块时，不在这两列之间换行。所以一个接一个的阶段在同一行里从左到右排列。
  - `loop` 与 `structure` 线当作从驱动指向回路，所以驱动排在回路前面。
  - 训练模块作为一个整体排列。子画布里的成员在子画布里排好，左栏的段落不参与整理。框的左边为左栏留出宽度，所以框不会压住旁边的模块。
  - 没有输入的模块放在第一个使用它的模块前面一列，而不是最左边。
  - 同一列里，模块按上下游的位置排序，以减少交叉。模块也尽量和给它输入的模块对齐，让线走得直。
  - 放置模板时，组合连同里面的每个子组合一起排好。折叠的子组合里面也提前排好。
  - 展开或折叠组合后，它所在组合的那一层重新排版。画布最外层只在有模块互相压住时才重排，所以你手动摆放的位置保留。
  - 浏览器量出新展开模块的实际尺寸后，整理再微调一次。这次微调算进同一步撤销。
  - 工具栏的“整理”：选中模块时，只排选中的部分。选中的正好是某个组合的全部成员时，按整个组合排。什么都没选时，整理整张画布。
- 工作区自动保存：
  - 工作区自动保存在 `localStorage`（键 `neurom-workbench`），按来源隔离。工作区包括模块图、连线、组合、运行、产物、数据集、我的模板、视角与连线外观。
  - 要跨端口或域名使用工作区，先导出，再导入。
  - 同一来源的多个标签页共用这一份保存。标签页只在自己改动后写入，所以刷新或关闭一个过期的标签页不会用过期的状态覆盖保存。没有未保存改动的标签页跟随其他标签页的保存，有训练在运行时除外。
- **冲突面板**：
  - 本地保存的工作区可能无法恢复。原因可能是：它不是 JSON、格式标签不同，或者校验不过（例如配置里有未知字段）。这时页面不换成空工作区，而是打开冲突面板。面板显示找到的格式、出错位置和原因（ADR 0008）。
  - 面板打开期间，本页不写这份保存：不自动保存，也不响应其他标签页的保存。
  - 面板提供三个操作：
    - **导出本地存档**：下载原样的 JSON。
    - **打开改好的文件**：和“打开”一样严格校验。通过后，面板关闭，这个文件成为工作区并保存。
    - **丢弃本地存档**：再确认一次后删除本地存档，从空工作区开始。

## 模块种类

| 种类 | 作用 | 端口 |
|---|---|---|
| 文字 | 说明文字 | — |
| 参数 | 声明字段（int / number / boolean / enum / string，范围、默认值）和函数输入，并填值。表单自动生成。声明在弹框里编辑。标题栏折叠按钮左侧的 ⚙ 打开弹框。弹框左侧是可视化编辑，右侧是 YAML。范围和选项可以写成引用其他字段的约束表达式（例如 `max: grid - 1`）。值越界时报错，并阻止打包。接入的代码计算派生值，例如由字段推出的查找表。多个函数输入的结果按键合并，同一个键只能有一个来源 | 每个函数输入一个调用端口（默认 `options`）。输出整体对象 `params`（可展开字段） |
| 代码 | 一份受限 JavaScript 文件（不写类型），只有顶层 const 和 function。导出即端口。导出函数的角色由它接到的端口决定（见下文）。场景也是代码模块：它导出 `init`（可选）、`input`、`step` 和 `budget`（可选 `actions`），经 `module` 交给回路运行 | `inputs` 里每个名字一个值输入。每个 `export function` 一个调用输出，每个 `export const` 一个值输出，另有 `module`（整个文件） |
| 数据集 | 导入 CSV / JSON（文件、拖放或粘贴），记录列、行数与内容哈希。数据存在 IndexedDB | 输出 `table` |
| 分区 | 训练 / 验证 / 测试三种角色的回合来源。来源有种子区间、枚举组合和时间窗。枚举组合中，每个角色取全部、奇偶、下标列表或 `{ mod, rem }` 余数筛选。时间窗有长度、步长和隔离带 | 输入 `table`（可选）。输出三种 `partition` |
| 随机数 | 32 位线性同余生成器的跳跃表。配置是乘数、增量、表长（默认 1664525 / 1013904223 / 512）。卡片显示取数公式和前几个值 | 输出 `rng: { mul, add }` |
| 回路 | 回合每一步的边界。回路把场景 `input` 的输入位送进回路体，再把回路体的动作收回交给 `step`。回路体是从 `input` 到 `action` 的连线路径上的模块（网络、读出、位线）。回路通常画成回路框。单独放时，卡片显示场景状态、I、回路体摘要和驱动 | 调用 `scenario`（场景的 `module`）。值 `action`（下一步生效）。输出 `input`（bits[I]）、`loop`（句柄） |
| 读出 | 分数 → 动作。模式有两种：`argmax` + 映射表（`null` = 无效动作），或 `bits` + 解码。两种模式都有函数输出 `run`：先做它的网络前向，再给出读出位。`bits` 模式按位读出，`argmax` 模式给出 argmax 的 one-hot 位（并列时取最小下标）。`run` 可以作为工具层的工具。用 argmax 读出的工具不能部署到链上 | 输入 `scores`、`actions`。输出 `action`、`bits` 和调用输出 `run` |
| 网络 | 整数网络，格式有两种。`dense-policy`：FF / LIF，层列表包含普通层 `{ hidden }` 与工具层 `{ tools, data? }`。在卡片上增删层、改层宽。多层与工具层都能部署，工具层里的代码工具和 argmax 读出的网络工具除外。`threshold-layers`：层宽列表。输入宽度 I 由配置 `inputs`（1–65535）手写声明，接到 `in` 的位宽必须等于 I。卡片显示权重字节数与部署上限。没有训练器训练这个网络时，在卡片上选定它运行的产物 `artifact`。可选工作区与内置产物，卡片显示名称、指标与兼容性，也可以导入 JSON。`artifact` 与 `weights` 连线二选一 | 输入 `in` 和 `weights`。`weights` 是训练这个网络时在候选里接受的权重，可以闭合回路。每个工具层一个调用端口，接任意多个工具。输出 `scores`、`structure` |
| 位线 | 位向量的切片与拼接（`parts: [{port, offset, width}]`），总宽 ≤ 65535 | 若干 `bits` 输入。输出 `bits` |
| 训练器 | 方法：REINFORCE / 交叉熵 / hinge。后端：浏览器或 Python。卡片有开始 / 取消、进度与曲线、运行列表。训练器在整条回路上训练 `structure` 指向的网络，其余网络冻结。回合来自 `training` 分区 | 值 `loop`、`structure`、`training`、`validation`。调用 `objective`、`metric`。输出 `run` |
| 候选 | 运行产生的产物：兼容性、预览、接受、导出、导入 | 输入 `run`（多个）。输出 `weights`、`artifact` |
| 评估器 | 每个网络用已接受的权重，在 `partition` 分区上贪心地运行整条回路，计算指标。评估器可以按枚举轴分组 | 值 `loop`、`partition`。调用 `metrics`、`objective`。输出 `report` |
| 执行实例 | 每个网络用已接受的权重，逐步运行整条回路。操作有选回合、reset / step / 连续运行和手动动作。历史记录每步的输入位和回路体每个模块的值。历史还记录每个工具层调用了哪个工具，以及它的数据位和结果 | 值 `loop`、`partition`。输出 `execution` |
| 视图 | 渲染执行实例或报告。渲染方式有 `grid`（地图 + 标记）、`series`、`table`、`kv` 和 `script`。`script` 是视图脚本（ADR 0013），在沙箱 iframe 里自己画 | 输入 `execution` 或 `report` |
| 链上部署 | 通过所选网络的官方 ModuleFactory 部署一份产物。带工具层的网络先部署或复用它的工具模块。链上部署还核对产物和它的工具、读状态、reset、逐步交易。本地镜像用来对照 | 输入 `artifact`。输出 `deployment` |

## 代码模块

所有逻辑都写在代码模块里：

- 场景（接到回路的 `scenario`）。
- 奖励。
- 监督目标。
- 指标。
- 参数模块的函数输入。
- 只求一次值的常量，例如场景的 `export const budget`。

导出函数接到的端口决定它的角色，端口规定签名。类型不符的调用线连不上。类型错误定位到行。

- 一个代码模块就是**一份文件**。文件只有顶层 `const` 和 `function`，在一个代码框里编辑，没有单独的函数头。模块标题只是标签，函数名写在源码里。
- **导出即端口**：
  - 每个 `export function 名称(…)` 是一个调用输出（ƒ）。调用方按这个函数自己的参数传参。
  - 每个 `export const 名称 = …` 是一个值输出，由输入静态地求值一次。
  - 另有输出 `module`（整个文件）。它交给按角色调用其中函数的模块，也就是回路（接回路的 `scenario`）。
  - 未导出的函数是辅助函数，在调用处内联。未导出的常量是普通常量。
  - 改源码时，端口随之更新。源码暂时编译不过时，端口保持上一次的样子。
  - 某个导出消失，或从函数变成常量（或反过来）时，它的连线在同一次编辑里断开。
- **输入**：代码框上方的 `inputs` 一行，用逗号分隔。
  - 每个名字是模块左侧的一个必需值输入，也是文件里处处可读的名字。它作为静态值绑定进读它的函数和常量。例如奖励的 `weights` 接奖励权重参数模块，场景的 `sense` 接感知参数，`rng` 接随机数模块。
  - 名字个数不变时，按位置改名，连线跟过去。个数变化时，接到已删名字上的线断开。
- 代码框下方列出报错，定位到文件 / 常量 / 函数 / 调用处，每条带“定位”按钮。「全文」tab 还列出不是角色的导出：ƒ 或值、名称、签名、接到了哪里（含 `module` 一行）。
- 函数上方是**注释**（JSDoc）：第一段是说明，然后是 `@param 名称 说明`、`@param 名称.字段 说明`、`@returns 说明`。工作台忽略标签里的 `{类型}`。类型只来自调用处和连线。说明文字出现在端口的悬停提示里。
- **角色页**（ADR 0012）：
  - 别的模块按协议调用的导出各有一个竖向 tab。这类导出是接到调用端口的函数，以及经 `module` 接到回路 `scenario` 的场景角色 `init / input / step / budget / actions`。
  - 训练模块里的代码模块合成一个「代码」节，按模块分组。
  - 角色页只显示这一个函数。
  - 参数个数正确时，函数头除参数名外锁定。行首有锁，悬停锁看说明。参数可以改名，但不能增删。参数和返回值后面用灰字标出类型，例如 `step(state: State, action: number) → { state, done, success }`。
  - 行尾的 **?** 打开可拖动的说明窗。说明窗写出：
    - 谁在什么时候调用。
    - 每个参数（记录可展开到字段）。
    - 要返回什么。
    - 一个例子：驱动回路的分区的第 1 个回合，动作取 0，真实运行得到的参数和结果。
  - 参数个数不对时，函数头不锁，**?** 标红。说明窗里有「改成 (…)」按钮。这个按钮按默认参数名改写参数表，只改函数头。
  - 缺的必需函数是红色 tab。可选函数收在 ⊕ 里。点开可选函数时，先预览要插入的代码，再点「添加」。预览按它接的回路写，和预制模块新建场景时一样：`input` 返回回路体读的位数。在说明窗里可以删除可选函数。
  - 「全文」tab 显示整个文件：辅助函数、常量、输入、其他导出。
- 其余名字的类型不在框里常显。像 VS Code 一样，悬停查看：
  - 指到名字上时，名字立即以带底色的方框标出。停留 300ms 后出现提示。提示显示时，移到别的名字上，提示立即切换。
  - 悬停函数名，看完整签名、说明、调用方和返回说明。
  - 悬停名字，看它的静态类型与注释。这适用于：
    - 函数参数。
    - 输入。
    - `const`（显示其上方 `/** … */` 的内容）。
    - 回调参数：属于哪个 `.map / .reduce / scan` 的元素、下标或累加值。
    - 字段，例如 `state.x`。
    - 记录字面量的键。
    - 内置函数与方法，例如 `sum`、`Math.max`、`.map`…：显示签名、用途和此处的返回类型。
  - 函数自己的参数按它的第一个调用处定型，也就是从这个导出拉出的调用线。场景模块经 `module` 接到回路的 `scenario` 时，参数按运行器调用这个角色时传的参数定型。
  - 输入按它的连线定型，常量按它依赖的名字定型。
  - 类型检查失败时，失败之前已推断出的类型照常显示。源码暂时无法解析时，不显示类型。
- **注释跟着值走**（像 TS 里属性的 JSDoc，在哪儿读都能看到）：
  - 函数参数和它的字段的说明来自传入方。所以不用在每个使用它的函数里重写说明。
  - 来源是第一个调用方：先是它的协议对这个参数的一句说明，下面是它传入的实参的说明。实参的例子：
    - 场景的 `State` 是 `init` 的返回值。没有 `init` 时，`State` 是分区的回合记录。
    - `Transition` 包着前后两个 State 和本步的 `action / done / truncated / success`，由回路发布。
    - 参数模块的函数输入收到参数模块自己的字段。
  - 输入的说明来自它的连线。
  - 参数模块的每个字段以声明作为说明：标签、类型、范围或取值、默认值。
  - 返回的记录：字段说明写在返回的对象字面量里，放在键的前面（`return { /** 智能体的 x 坐标 */ x: …, … }`）。
  - 没写说明的字段沿用放进去的那个值的说明：
    - `{ ...s, x }` 保留 `s` 各字段的说明。
    - 条件表达式取两个分支的说明。
    - `map` 的元素照旧保留说明。
  - 算出来的新值（算术、内置函数）没有说明。
  - 本函数注释里的 `@param 名称 说明`、`@param 名称.字段 说明` 优先于传入方的说明。只在需要改写时才写它们。
- 编辑器是 CodeMirror：
  - 源码按 JavaScript 语法着色，写到一半的代码也照常着色。
  - 出错的范围画波浪线，错误信息列在编辑器下方。
  - 输入时补全：`transition.` 之后列出这个值的字段和类型（按调用方传入的类型）。名字前缀列出作用域里的名字、内置函数和关键字。`Math.` 之后列出数学函数。
- 语法：
  - 支持的语法：解构、`const`、`return`、条件表达式、`if/else return`、对象字面量与展开（`{...s, x}`）、数组字面量、`.map / .reduce` 带内联箭头、`range(n)`、`u32 / imul32 / add32 / …`、`rand(key, counter)`、`Math.sqrt / log / exp`、`bucket / thermometer`、`table.at(i, 'col') / table.window(end, k, 'col')`、字符串字面量。
  - 函数参数只能是名字。
  - 不写类型。类型标注、泛型、`as / satisfies / !`、`type / interface` 都报错。类型由调用方决定，写在角色页的函数头上。
  - 工作台拒绝循环、赋值、导入、递归和任意动态调用。没有 `eval`。
- 模板与程序：
  - 模板里写 `config: { inputs: [...], source: |- … }`。`exports` 由源码推出，不用写。
  - 模块只导出一个函数（或一个常量）时，连线可以省略源端口（`reward→trainer.objective`）。
  - 每个导出函数和每个常量编译成一个 `neurom-program` 程序。浏览器与 Python 解释同一份程序。
  - 每个程序 ≤ 4096 个节点。`map / fold / scan` 长度是静态的，最坏代价有上界。
  - 奖励与指标可以用 `ln / exp`。

挖矿模板的奖励如下。导出的 `reward` 接到训练器的 `objective`。输入 `weights` 由值线 `weights.params→reward.weights` 接到一个参数模块。

```ts
/**
 * 奖励：结算价值增量乘价值系数，减每步成本与无效动作成本；回合结束时加成功奖励或减失败成本。
 * @param transition 本步转移
 * @returns 本步奖励
 */
export function reward(transition) {
  return weights.value * (transition.next.settledValue - transition.prev.settledValue)
    - weights.step
    - (transition.next.invalid ? weights.invalid : 0)
    + (transition.done ? (transition.success ? weights.success : -weights.failure) : 0);
}
```

## 场景模块

场景就是一个普通代码模块，没有单独的“环境”模块。场景的 `module` 接到回路的 `scenario`（`scene.module → loop.scenario`）。回路每一步按角色调用场景导出的函数。数据流是：状态 → `input` 编码成输入位 → 回路体（网络 → 读出 → …）→ 动作 → `step` 得到新状态。协议见 [设计 §3 场景模块](../docs/design.md#场景模块)，包括角色、`Transition`、`budget`、`actions`、场景参数和网络看到什么。画布上：

- 场景的问题报在回路的 `scenario` 端口上。问题包括缺角色、类型错误和缺 `budget`。
- 在场景模块的导出列表里，未直接接线的角色函数显示运行方与角色。例如“经 module：回路 的 step”。悬停角色函数，看运行器传入的参数类型。

## 工作流

1. **放置任务**：在“添加”里选一个示例或一个组合模板。
   - 示例是模板实例。只有四位算术与组合器带已接受的内置产物。挖矿和记忆地图放置后，网络没有权重，所以要先训练。
   - 挖矿任务展开后有 18 个模块，都在训练模块 **挖矿** 里：
     - 左栏：种子分区、环境参数、感知参数、随机数、场景、奖励权重、奖励、三个指标、训练器、候选、评估器、执行实例和地图视图。
     - 右边的子画布：**回路**（回路框：网络 → 读出）。
     - 子画布左边的七个探头：场景 · module、场景 · actions、训练器 · structure、训练器 · loop、评估器 · loop、执行实例 · loop、候选 · weights。
2. **改规则**：
   1. 展开组合。
   2. 在左栏环境段落的环境参数中，改网格、步数、结算方式、交付后是否结束回合。
   3. 在感知参数中，改方形视野半径。

   范围写在参数声明里，可以是引用其他参数的表达式（例如基地坐标 `max: grid - 1`）。值越界时报错，并阻止打包。场景模块的 `input` 决定网络的输入。读出模块的映射表决定动作槽是否起作用。环境参数和感知参数都不进入网络，只有编码后的输入位进入网络。

   改场景模块就是改场景。环境相关的东西包括场景模块、它的输入、`budget`、驱动分区的回合种类。改了其中任何一项后，候选把旧产物标为“环境不同”。
3. **训练**：
   1. 在训练器里选后端（浏览器 Worker 或 Python Workspace）、方法与配方。
   2. 点开始。

   训练器沿输入收集**训练快照**（环境 + 回路 + 目标 + 分区 + 配方）。之后改画布不影响运行中的训练。回路里的其他网络必须已有产物，训练时冻结运行。工具层调用的网络也一样，例如组合器的 ADD4 / SUB4 / MUL4，它们各自选定了 `artifact`。

   进度、loss 与指标曲线实时显示。训练可以取消。训练完成只产生候选。
4. **候选**：候选列出每次运行的产物：方法、后端、指标、结构、兼容性。在候选里可以预览、接受、导出 JSON、导入 `neurom-module` 产物。接受后，权重流向网络。
5. **评估**：
   1. 在评估器里选角色（默认测试分区）。
   2. 运行评估。

   报告包含各指标均值、成功率、每个网络用的产物和样例。枚举分区可以按轴分组画曲线：记忆地图按延迟画保留曲线，组合器按运算分组。
6. **执行**：
   1. 在执行实例里，从接入的分区选回合（种子 / 枚举记录）。
   2. 使用 reset、step、连续运行或手动动作。

   每个网络用已接受的权重。历史里显示每步的输入位、回路体每个模块的值、动作、电位和这一步怎样结束。带工具层的网络还写出这一步调用了哪个工具、交给它的数据位和它的结果。只有这个工具运行了。视图订阅执行实例，渲染地图或曲线。
7. **部署**：
   1. 在链上部署模块里选网络。
   2. 连接。
   3. 部署一份产物。
   4. 核对、读状态、reset，或逐步发交易。

   链上部署模块用这个网络的**官方 Factory**（ADR 0016）。Factory 地址写在 `chain.js` 的 `CHAINS` 里，不用手填。面板显示这个地址，有区块浏览器的网络带链接。本地镜像用产物快照里的同一环境与整数执行器逐项对照。

   别的 Factory 创建的模块即使代码和权重完全相同，核对也不通过，也不会作为工具复用。还没有官方 Factory 的网络（目前是测试网和主网）会直接说明这一点。在这些网络上不能部署和核对。

   Local dev 用 `http://127.0.0.1:18545` 的 Anvil 解锁账户。如果节点是新启动的 `anvil --network monad`，先用默认账户 0 运行 `contracts/script/Deploy.s.sol`。这样 Factory 代理才落在 `CHAINS[31337].factory` 的地址。部署 / step / reset 是交易，预览是 eth_call。
8. **存模板**：
   1. 选中模块或组合。
   2. 点“存为模板”。

   在模板库里可以实例化、分叉、导出 / 导入 YAML。画布上每个来自模板的组合显示 `id@revision`。实例不随模板更新。

回路体的规则：

- 每个网络的 `in` 恰好接一次。宽度不符时拒绝连接，不补零，不截断。
- 读出显式选择 argmax 或位。
- 位线把回路的输入位或一个网络的输出位切片、拼接，然后喂给多个网络。
- 工具层调用的工具不属于回路体。每一步只运行选中的那个工具。

组合器示例：`input` 11 位 → 策略网络的工具层选出 ADD4 / SUB4 / MUL4 之一，交给它 8 个数据位 → 它的结果位 → 位读出 → `action`。

## 状态边界

- 训练运行、执行实例、评估各自持有状态。同一回路的不同执行实例不共享回合、电位或历史。多个视图可以观察同一个执行实例。
- 执行实例只在显式 reset 或换回合时清理时间状态。画布改动后，正在运行的快照标为过期。reset 后，执行实例按当前画布重建快照。训练编辑、候选预览、布局变化不影响它。临时回合、电位、历史不随工作区保存，所以重开后从初始状态执行。
- 评估报告描述评估运行时固定的快照。画布改动不丢弃也不重算报告，评估进行中的改动也一样。画布改动只把报告标为过期，重新评估后报告更新。报告不随工作区保存。
- 训练运行固定开始时的快照和它读的数据表行。浏览器训练与 Python 训练拿到同样的行，Python 端把行随运行保存。重新导入数据集时，行写到新的内容 id，旧 id 的行不变。所以固定了旧行的运行和复制的数据集模块照旧可用。
- 工作台只在载入工作区（启动、打开文件）时回收数据表行。回收的行必须没有任何东西引用，而且写入已超过 10 分钟。原因是别的标签页可能刚导入这些行，还没保存。
- 浏览器训练在 Web Worker 里运行。关闭页面会中断训练，重开后训练标为失败。Workspace 持有 Python 运行，刷新后重新接上。
- 候选的兼容性按快照判断。以下三项与接候选的训练器一致时，才能接受产物：
  - 环境（快照的 `env`：场景程序、budget、动作表、回合种类、数据表）。
  - 训练器训练的网络的结构。
  - 读出规格。
- 手动步不调用模型。LIF 在回合内跨决策保留电位。视图不会把视野外的格子和隐藏目标泄露给模型。

## 界面语言

顶栏右侧的“中 / EN”切换界面语言。选择保存在 `localStorage`（`neurom-locale`）。首次打开时，界面按浏览器语言显示。切换即时生效，不重载页面，不影响训练和执行。

- 中文原文即词条键。英文界面下，`t('训练已取消')` 查 `i18n/en.json`。查表后，填入 `{name}` 占位符。缺词条时显示中文。
- 用户自定义的标题和模板名原样显示。模块种类标签、内置模板的名称、说明和示例标签经 `t()` 翻译。
- `npm test` 中的 `i18n.test.js` 运行 `i18n/check.mjs`。它检查以下规则：
  - 每个中文字面量、Vue 模板文字、`index.html` 静态文字、内置模板 YAML 的 `name` / `description` / `preset.label` 都必须有英文词条。
  - 英文词条的占位符和 HTML 标签与原文一致。
  - 没有未使用的词条。
